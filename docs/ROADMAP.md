작성 2026-09-04. 근거는 `docs/` 전체를 5개 축으로 추출하고 세 관점(논문화·정확도·안정성)으로
각각 우선순위를 매겨 비교한 결과입니다. 원본: `docs/raw/roadmap_raw.json` (후보 76건).

## 먼저: 불편한 진단

세 관점이 **독립적으로 같은 결론**에 도달했습니다. 이걸 먼저 받아들이지 않으면 다음 단계가 전부 어긋납니다.

### 1. 현재 수치는 승리가 아니라 무승부입니다

| 측정 | SAM 3 | SAM 2 최고 | 차이 |
|---|---|---|---|
| 헤드라인 (15개, object-pooled) | 0.8451 | 0.8434 | **+0.0017** |
| 데이터셋 단위 표준오차 | — | — | **±0.006** |
| 짝지은 부트스트랩 | 15개 중 8승 | — | CI **[-0.0080, +0.0109]** |
| DAVIS식 시퀀스 단위 집계 | 0.8381 | 0.8358 | +0.0023, OneStage는 **정확히 동타** |
| 면적 가중 J | 0.9253 | 0.9254 | **효과 소멸** |

**신뢰구간이 0을 넘어갑니다.** 집계 방식을 바꾸면 차이가 사라집니다.
`docs/experiments.md`는 집계 방식을 명시하지 않는데, 그게 수치를 움직입니다.

### 2. 핵심 메커니즘이 한 번도 절제(ablation)되지 않았습니다

교차시점 메모리가 논문의 주장인데, **그것을 끈 대조군이 존재하지 않습니다.**

- `OneStage` vs `OneStageNew` 비교는 대조군이 아닙니다 — 패키지·`sys.path`·요청 형태·세션 수가 전부 다릅니다.
- 이웃이 0개인 index-0 카메라 8대조차 OneStage와 매 프레임 다릅니다 (C2 결함 때문).
- `range(-4, 0)` 윈도는 **한 번도 변경 실행된 적이 없습니다.**

리뷰어가 오후 한나절이면 찾아낼 구멍입니다.

### 3. SAM 2 비교가 동일 조건이 아닙니다

| 항목 | SAM 2 | SAM 3 |
|---|---|---|
| `fill_hole_area` | 8 | 0 |
| non-overlap 제약 | 끔 | 켬 |
| 저해상도 | 288 | 256 |

주장하는 우위는 **전부 F(+0.006)에서 나오는데, 위 설정 차이가 같은 크기**입니다.
게다가 인용 중인 `SegMaskNew1`은 설정이 기록되지 않은 6개 열 중 가장 좋은 것이고,
재현 실험은 `SegMaskNew3`를 재현했습니다.

### 결론

**다음 작업의 목표는 J&F를 0.001 더 올리는 것이 아닙니다.** 이 효과 크기에서 그 싸움은 이길 수 없습니다.
목표는 **관측된 차이를 귀속 가능한 메커니즘으로 바꾸는 것**입니다.

## 단계

### Phase 0 — 현재 상태 보존 (1일, GPU 불필요)

추론 코드를 건드리지 않으므로 어떤 수치도 바뀌지 않습니다.

| 항목 | 내용 |
|---|---|
| `memcap-two-scripts` | `runMVSegAll.sh`·`launch_container.sh`에 `--memory=90g` 추가. 지금 없어서 전체 스윕이 머신을 다운시킬 수 있습니다(실제로 2회 발생) |
| `backup-tag-not-tmp` | `/tmp/sibling_backup`을 git 태그로. 재부팅하면 사라집니다 |
| `push-and-purge-token-image` | 미푸시 커밋 푸시, `scsam3:pre-secret-backup` 정리(마지막 토큰 보유 이미지) |

**완료 조건**: `git status -sb`에 ahead 없음, 네 개 실행 스크립트 전부 `--memory=90g` 보유,
토큰 보유 이미지에 태그 없음.

### Phase 1 — 기록을 정직하게 읽기 (1주, GPU 불필요) ★ 가장 중요

**이 단계가 이후 전부를 바꾸거나 죽일 수 있고, 아무것도 망가뜨릴 수 없습니다.** 그래서 먼저 합니다.
디스크에 이미 있는 파일만으로 계산합니다.

| 항목 | 내용 | 예상 결과 |
|---|---|---|
| `stats-ci` | 짝지은 부호검정 + 부트스트랩 CI | 과장을 방어 가능한 주장으로 |
| `agg-protocol` | 집계 방식 명시 (object-pooled vs per-sequence) | 격차 축소, OneStage는 동타 |
| `nonref-split` | 기준/비기준 카메라 분리 | **비기준 Δ +0.009** — 헤드라인 +0.0017보다 큼 |
| `eval-protocol` | 이웃 수 구간, 면적 가중, `--common` | nb=4 **+0.0047** vs nb=0 **-0.0001** |
| `seed-quality-diag` | 데이터셋별 퇴화 시드 집계 | Welder 손실의 원인 규명 |
| `mask-provenance-manifest` | 마스크 트리마다 git revision·실행 인자 매니페스트 | `Data/`가 gitignore라 지금은 mtime이 유일한 기록 |
| `onestagenew-column` | 논문이 보고할 SAM 3 열 하나를 확정 | `experiments.md` (2) 참조 |

**완료 조건**: `report_jf.py` 하나로 논문의 모든 표가 재생성되고, `--split`·`--bin-by-nb`·`--paired`·
`--area-weighted`를 지원. 그리고 **어느 엔드포인트가 주장을 감당하는지(또는 감당하는 것이 없는지)를
문서로 결정**.

> 비기준 카메라에서 +0.009라면, 헤드라인이 아니라 **거기가 논문의 주장이어야 합니다.**
> 메커니즘상 교차시점 메모리는 비기준 시점에만 작용하므로 이론과도 맞습니다.

### Phase 2 — 없는 대조군 만들기 (2주)

논문 전체가 여기에 걸려 있습니다.

| 항목 | 내용 |
|---|---|
| `xview-hygiene-c1-c2` | 음수 이웃 인덱스 clipping(C1), 조건부 출력 clobber 제거(C2). **한 줄짜리 수정 두 개** |
| `closure-track-mode` | `--track-cams closure` — 스윕 비용 5배 절감 (Welder 553초 → 약 60초) |
| `xview-window-param` | 윈도를 파라미터로 (`--xview-window N`) |
| `xw0-control` | **W=0 vs W=4, 15개 데이터셋** — 이 방법이 가진 적 없는 첫 유효 대조군 |
| `cpu-only-tests` | 메모리 수정 7종의 불변식을 테스트로 고정 (지금은 문서로만 존재) |

**주의**: C1/C2를 고치면 출력이 바뀝니다. **0.8451과 다른 시스템이 됩니다.**
논문은 한 계열을 택해 끝까지 그것으로 보고해야 합니다 — 위생 수정본의 W 곡선을 동결된 헤드라인 옆에
나란히 두면 안 됩니다.

**완료 조건**: `--track-cams closure`가 `all`과 바이트 동일, `SegMaskSam3XW0`/`XW4`가 15개 전부 존재하고
채점됨, 순효과가 비기준 분할·이웃 수 구간·짝지은 CI로 보고됨.

### Phase 3 — 측정된 손실 회복 (3~4주)

Phase 1·2의 도구가 있어야 결과를 귀속할 수 있습니다.

| 항목 | 근거 있는 기대값 |
|---|---|
| `seed-repair` | **정량화됨**: Welder 0.8437 → ~0.879, 헤드라인 **+0.0023~0.0027**. 유일하게 수치가 있는 정확도 항목 |
| `two-sided-window` | Fencing ~**+0.02** (−0.021 결손 대부분 회복). 다만 **추론이지 측정이 아님** |
| `ceiling-refrule` | 기준시점 선택 규칙 수정. Blocks +0.128, MATF +0.087, FacePaint +0.061 — **모든 방법에 동일 적용, 순위 불변** |
| `neighbor-objptr` | 미사용 채널. 사전 선언한 기준(비기준 +0.005 초과)으로 채택/기각 |

각 항목은 **실행 전에 합격 기준을 문서화**하고, 못 넘으면 측정값과 함께 닫습니다.

### Phase 4 — 비교를 공정하게 (1~2주)

| 항목 | 내용 |
|---|---|
| `sam2-config-match` | `apply_postprocessing=False`, `non_overlap_masks=True`로 SAM 2 재실행. **F +0.006이 사라질 수도 있습니다** |
| `sam2-provenance` | 인용 중인 SAM 2 열의 생성 스크립트·설정을 특정하고 재현 |
| `fill-hole-area` | SAM 3에서 {0, 8, 16} 측정 |
| `crossview-seed-oracle` | GT 시드 상한선 — 남은 오차를 시딩과 추적으로 분리 |

### Phase 5 — 엔지니어링 부채 (여유 시간에)

`seeding-response-skip`(시딩 시간 120~260초 → 수초), `twostage-verify-or-revert`(등록하거나 되돌리거나,
중간 상태 금지), `forsam2new-path-analysis`(무거운 3개가 여전히 OOM인 이유 규명).

## 하지 말 것

`docs/analysis/SCHEDULE.md`가 금지한 것들입니다. 근거가 문서에 있습니다.

| 항목 | 이유 |
|---|---|
| **fp16 프레임 저장** | 소비자의 fp32 캐스트가 버린 가수 비트를 복구 못 함 → **마스크가 바뀜.** fp32(S5)가 여기서 얻을 수 있는 전부 |
| **bf16 autocast 컨텍스트 변경** | `decoder.py:71`이 의도적으로 fp32로 도는 FFN 구간이 깨짐 → **모든 마스크가 바뀜** |
| **프레임마다 `clear_autocast_cache()`** | 피크 감소 없이 프레임당 ~5 GiB HBM 트래픽 추가. 경계에서 정확히 한 번만 |
| **시점 전파 시작 인덱스 명시** | Blocks 0.7484 → 0.2827. `investigations-closed.md` 4번 |

## 순서에 대한 한 가지

세 관점이 기간은 다르게 봤지만(논문화 25일, 정확도 10주, 안정성 11주) **순서는 같았습니다**:

> 보존 → **정직한 측정** → 대조군 → 정확도 → 공정한 비교 → 부채

특히 **Phase 1을 GPU 없이 먼저** 하는 데 셋 다 동의했습니다.
비기준 분할에서 +0.009가 나온다면 Phase 3의 우선순위가 완전히 달라지고,
반대로 어느 엔드포인트에서도 CI가 0을 넘지 못한다면 Phase 2의 대조군이 더욱 급해집니다.

**Phase 1을 건너뛰고 정확도 작업부터 하면, 나온 결과를 해석할 방법이 없습니다.**
