# SAM 2 기준선 — 무엇이 재현되고 무엇이 안 되는가

**일자**: 2026-09-09 · **GPU**: CoffeeMartini 2회(24분 + 28분) · **이미지**: `scsam2` (fb5fc1426874, torch 2.6.0+cu118, python 3.11)
**배경**: Phase 4(공정한 SAM 2 비교, REPORT E6·실험 행 11)를 시작하기 전에, 논문이 인용하는 SAM 2 열이 지금 재현되는지부터 확인했습니다.

---

## 1. 결론 셋

1. **논문이 인용하는 `SegMaskNew1`은 git의 어떤 상태로도 재현되지 않습니다.** 오늘 코드는 `SegMaskNew3`를 바이트 단위로 재현하고, 그 이전 커밋(ec81251)의 예측기도 `New1`을 재현하지 못합니다.
2. **재현 가능한 SAM 2 계보는 `SegMaskNew3`입니다.** 따라서 논문의 SAM 2 열을 `New3`로 바꾸는 것이 옳습니다. 15개 평균 J&F는 0.8434 → 0.8433으로 0.0001 바뀝니다.
3. **REPORT E6의 설정 불일치 두 가지 중 하나는 존재하지 않았습니다.** SAM 2의 `fill_hole_area=8`은 이 환경에서 아무 일도 하지 않습니다.

## 4. `fill_hole_area`는 실행된 적이 없습니다

SAM 2 빌더는 `fill_hole_area=8`을 넣지만(`SCSam2/demo/build_sam.py:266`), 그 함수는 컴파일된 확장 모듈 `sam2._C`를 필요로 합니다. 이 이미지에는 그 모듈이 없어 함수가 경고만 찍고 **입력을 그대로 반환**합니다. 직접 확인했습니다.

```
same object returned: True      any pixel changed: False      hole still negative: -5.0
warnings: ["cannot import name '_C' from 'sam2' ... Skip"]
```

발표된 마스크에도 1~2픽셀짜리 구멍이 남아 있어(구멍 메우기가 돌았다면 불가능) 당시에도 무효였음이 확인됩니다. **REPORT E6이 든 설정 불일치 두 가지 중 구멍 메우기는 애초에 존재하지 않았습니다.** 남는 것은 출력 단계의 겹침 제거 하나이고, SAM 2는 적용하지 않는 반면 SAM 3는 객체별 점수 기준으로 적용합니다.

또한 내부 마스크 해상도 256 대 288은 체크포인트에 딸린 성질이라 **맞출 수 없습니다.** Phase 4 이후에도 남는 교란 요인으로 논문에 적어야 합니다.

## 5. 이 조사가 바꾸는 것

1. **논문의 SAM 2 열을 `SegMaskNew3`로 바꿉니다**(평균 0.8433). 재현 가능한 계보를 인용하는 것이 재현 불가능한 것보다 낫고, 비용은 0.0001입니다.
2. **REPORT E6을 정정합니다.** 구멍 메우기 항목은 삭제하고, 겹침 제거 하나와 맞출 수 없는 해상도만 남깁니다.
3. **Phase 4(설정 맞춘 재실행)는 `New3` 계보 위에서 진행합니다.** 바꿀 것은 출력 겹침 제거 한 가지이고, 이는 SAM 2를 다시 돌리지 않고 객체별 점수만 있으면 사후에 적용할 수도 있습니다.
4. **실험 행 11의 출력 이름 `SegMaskNew1_matched`를 폐기합니다**(재현 불가능한 열을 가리키므로). 대체 이름은 `SegMaskSam2Matched`입니다.
