# S1-E0″ 사전 등록 — 프레임 0을 재예측 대신 원시 시드로 쓰면 얼마나 오르는가

> 2026-09-10. 사용자 제안("2단계에서 원시 시드를 넣고 프레임 0에서 재예측하지 말자")의 크기를 먼저 잽니다.
> 층: 탐색. [stage1-E0.md](stage1-E0.md) §3의 체인상 프레임 1~20은 프레임 0에 **무엇을 쓰든** 바뀌지 않으므로
> (트래커 기억은 288 로짓 → 1008 → 기억 인코더 72×72에서 만들어지고, 출력 PNG는 기억에 영향을 주지 않음),
> 본류를 다시 돌리지 않고 **기존 출력 폴더의 프레임 0 PNG를 시드 PNG로 바꿔 채점**하면 새 옵션
> `--frame0-seed`(접미 `Fs`, 구현 중)를 켜고 돌린 것과 같은 결과입니다. GPU 0.

## 1. 절차
- 원본: `SegMaskSam3XW0M`(대조군), `SegMaskSam3XW1CGPS4M`(채택 구성), 17장면, 주석 카메라 3대.
- 파생: `SegMaskSam3XW0MFs`, `SegMaskSam3XW1CGPS4MFs` = 원본 복사 후 `<cam>/<start_frame>/<obj>.png`를 `MVSeed_e0_index/<cam>/<start_frame>/<obj>.png`로 교체(시드가 있는 객체만; 없으면 원본 유지). MANIFEST에 파생 표시.
- 채점: `eval/eval_jf.py` → `eval/report_jf.py --muvod --objects basic --ref-rule muvod`, 짝지은 Δ(17장면·클러스터 CI).

## 3. 읽기 규칙
- 이득은 "공짜"이므로 **Δ ≥ 0이면 `--frame0-seed`를 E7 등록 구성에 포함**하고, Δ < 0이면 포함하지 않음. 크기(예측 a)가 맞는지 대조표로 보고.
- 이 결과는 "재예측 제거"가 2단계에 미치는 효과의 **전부**입니다(프레임 1~20은 구성상 불변). 작은 객체의 손실은 프레임마다 288 격자에서 생기므로 별도 항목([stage1-E0.md](stage1-E0.md) §6-3)에서 다룹니다.
