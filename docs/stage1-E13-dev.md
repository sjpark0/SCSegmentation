## 3. 읽기

1. **MUVOD 규약 안에서는 덜 덮음 블록(약 0.6점)을 1단계가 회수할 정보원이 없습니다.** c_ini에서 나오는 모든 신호(재투영, SAM 3 프롬프트, 3D 성장, 디코딩 규칙 E11, 학습 재배치 E12)가 이미지 밖·깊이 없음 영역으로 객체 정체성을 옮기지 못합니다.
2. **규약 밖 정보도 거의 돕지 않습니다**: 객체 이름은 실패하는 큰 환경 객체를 검출하지 못하고, 두 번째 주석 카메라조차 범위 부족의 약 10 %만 닫습니다. 덜 덮음은 "어떤 카메라도 라벨하지 않은 범위"에 가깝습니다.
3. **판정**: S1-E13은 키프레임에 아무 팔도 보내지 않고 개발 집합 음성으로 닫습니다. 헤드라인 92.626 / 87.954와 `geoset_rep_x` 유지.
4. **남은 결정(사용자)**: (1) "객체 이름 + 유형"을 입력으로 쓰는 **별도 트랙**을 받아들일지 — 받아들이면 남은 개발 프레임(DEV-B: ref+1·2·3·5·…·19, 15프레임)으로 사전 등록 확인 한 번(GPU 약 1시간), 키프레임 결과는 같은 실패 객체에 몰려 독립 증거가 아님; (2) 규약 안 마지막 시도(seed 상자 자기 예시 검출, 코드 1시간·GPU 10분, 사전 확률 낮음)를 할지; (3) 다음 1단계 노력의 자리 — 좋은 시드 경계 오차 1.757점(가장 큰 블록), 같은 이름 혼동 0.45점, 띠 BCE 균형 재시험, S2-R6 확장; (4) 개발 집합 경로(`dev_decode.py`·`dev_score.py`)를 추적 코드로 옮겨 앞으로 모든 1단계 등록의 표준 개발 집합(DEV-A 탐색 / DEV-B 확인)으로 삼을지.
