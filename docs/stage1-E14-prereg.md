### 2.2 규칙 (상수 전부 여기서 고정)
`run.decode_scene`의 라운드 2 출력, 분기 `zoom is None and xcl != 'none'`에서, 대상 카메라마다:
- L = `sam3_io.logits_to_original(out["logits_1008"], hw)[:, 0]` — 채택 코드 그대로(쌍선형 두 단계).
- **pos_b = L_b > −XCL_SHIFT**, `XCL_SHIFT = 0.5`(모듈 상수, CLI 손잡이 아님). 문턱은 **비교로** 적용합니다(L에 더하지 않음). 그래서 argmax는 이동 전 L에서 계산되고, float32 반올림이 새 동률을 만들 수 없습니다. DEV-A 후보 채점(`tu_variants.py`의 `pos = L > −τ`, argmax는 τ와 무관)과 같은 정의입니다.
- w = argmax_b L(화소별; 정확한 동률 → 낮은 객체 인덱스; 부재 객체는 −1024라 이기지도 pos도 못 됨).
- lost_b = |pos_b ∧ (w ≠ b)|; exempt_b = lost_b ≥ 0.5 · |pos_b| (`XCL_TAU_KEEP` 0.5, 이동된 pos에서 계산); keep_b = pos_b ∧ (w = b ∨ exempt_b).
- 나머지 전부 채택 그대로: θ 0.5, MIN_VALID 64, τ 0.7, k 3, OBJ_CHUNK 8, gate reproj, 장면마다 자기 폴드를 보류한 `geoset_pred_ft` 체크포인트, zoom 꺼짐, 라운드 1·기억 인코딩·업샘플러 불변.
- 결과로 성립해야 하는 것: 보호가 켜짐 → 꺼짐으로 뒤집힌 객체를 빼면 팔 마스크 ⊇ 기저 마스크(제거 0); 새로 가진 화소는 그 객체가 argmax인 화소뿐; 어떤 마스크도 비워지지 않음(전부 잃으면 보호됨).
- config.json에 `xcl = "outs"`, `xcl_shift = 0.5`를 적습니다. `none`·`out`·`outmem`·`out_nocap` 경로의 출력은 바이트 동일합니다(Z4).

### 2.3 상수 τ = 0.5를 고른 방법 (DEV-A만; 탐색 규칙과 다름을 선언)
탐색 단계의 사전 규칙(`MVSeed/refloss/e14/threshold-upsample/PREREG.md`, 채점 전 sha256 기록)은 "모든 쌍 ΔJ&F 최대"로 τ = +1을 골랐습니다. 등록에서는 **키프레임 관문 모양의 규칙**으로 바꿉니다: DEV-A 의사 키프레임 5개 모두에서 G1(CI 하한 > 0)·G2(어떤 장면도 < −0.01 아님)를 통과하는 τ 중 모든 쌍 ΔJ&F가 가장 큰 것. 결과: 0.25 5/5(+0.0019), **0.5 5/5(+0.0028)**, 1 4/5(+0.0031; 한 오프셋에서 CI [−0.0010, +0.0059], 최악 장면 −0.0131), 1.5 0/5 → **0.5**. 근거를 더하면 CI가 더 좁고(+0.0028 [+0.0013, +0.0047] 대 +0.0031 [+0.0005, +0.0059]), 최악 장면 위험이 작고(Dog −0.0029 대 −0.0091), 장면 하나 빼기에서 {0.5, 1}이 뽑히고, E9 D1에서 재현됩니다. 프로토콜 §3.1은 상수를 DEV-A에서 고르도록 허용하며, 보호 대상은 DEV-B와 TEST뿐입니다.
