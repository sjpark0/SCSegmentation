### 3.1 각도와 별/릴레이 나눔
- r = c_ini. 작업 해상도 = π³ 캐시 해상도(약 378×672). valid_v = (conf > 0.1) ∧ (depth > 0).
- **객체 기준점** X = c2w_r[:3,:3] · median(local_points(D_r)[(∪_o M_o)_w ∧ valid_r]) + c2w_r[:3,3]. M_o는 c_ini 입력 마스크입니다. 합집합의 유효점이 N_min보다 적으면 장면 기준점(진단 정의, `ring_diag/baselines.py`)을 씁니다.
- **c_ini에 유효한 π³ 점이 하나도 없으면**(코드가 정한 것을 등록, 2차 검토) 기준점이 없습니다. 그 프레임은 모든 뷰가 S이고 F = ∅이므로 디코딩은 C0와 같습니다. 이유는 relay.json의 `fallback`에 기록합니다.
- C_v = π³ 카메라 중심. a_v = ∠(C_r − X, C_v − X). hop(m, v) = ∠(C_m − X, C_v − X).
- 별 뷰 S = {v ≠ r : a_v ≤ θ_s}. 먼 뷰 F = {v : a_v > θ_s}.
- θ_s = ∞이면 F = ∅이고 릴레이는 꺼집니다.
- F는 입력만으로 정해집니다. 판정에 쓰는 F는 디코딩 전에 추적 코드(`run.relay_geometry`)로 계산해 `stage1/scripts/e15/runs/angles.json`에 적습니다(Step 0, M5).

**입력 객체 집합(기준점의 입력, M1).** 점수를 보기 전에 정하고, 본 뒤 바꾸지 않습니다.

### 3.2 Fix A 공통 (새 모듈 `stage1/geomem/id3d.py`, torch 없음)

**좌표.** P_v(x) = to_reference(local_points(D_v, K_v), c2w_v, c2w_r) / s. s = c_ini의 scene_scale입니다. `pointmap.ref_frame_points`·디코더 격자와 같은 좌표·척도입니다.

**들어 올리기.** 마스크 m을 작업 해상도로 옮깁니다(INTER_AREA 덮음 ≥ 0.5 → m_w).
- L(m, v) = {P_v(x) : x ∈ erode₃ₓ₃(m_w) ∧ valid_v}.
- 점이 N_min보다 적으면 깎지 않은 m_w를 씁니다. 그래도 적으면 ABSTAIN(작음)입니다.

**판정할 마스크.** 원 로짓 L > 0입니다(`logits_to_original`, xcl 전). 기억 인코더가 보는 마스크와 같습니다.

**기준 모형.** 객체 o마다 c_ini 입력 마스크로 한 번 만들고 바꾸지 않습니다.
- R_o = L(M_o, r). c_o = 좌표별 중앙값. ρ_o = ‖R_o − c_o‖의 90 백분위.
- 모형 있음 ⇔ |R_o| ≥ N_min.
- 넓음(환경) ⇔ ρ_o > ρ_env.
- 잘림 ⇔ border_o > b_max. border_o는 원 해상도에서 M_o 화소 중 테두리 max(2 px, 0.5 %·min(H, W)) 안에 있는 몫입니다.
- 경쟁자 J_o = 모형 있고 넓지 않은 다른 객체. 잘린 객체도 경쟁자에 남습니다.

**상태.** {PASS, FLAG, ABSTAIN, EMPTY} 중 하나입니다.
- EMPTY = presence ≤ 0 또는 마스크 화소 0.
- 나머지는 통계(§3.3)가 정합니다. 통계가 PASS도 FLAG도 아니라고 하면 ABSTAIN입니다.

**신뢰(기억 conf).** conf(m, o) = presence > 0 ∧ (PASS ∨ (ABSTAIN ∧ 채택 reproj 규칙)).
- 채택 reproj 규칙 = `object_conf_mode("reproj")`: overlap ≥ 0.5, overlap이 NaN이면 IoU ≥ 0.7.
- FLAG와 EMPTY는 절대 신뢰하지 않습니다.
- Fix A가 판정하지 못하는 곳은 지금 게이트가 정합니다.

**리그 신뢰도(A-c\*에만 쓰는 선택 상수, L7).** φ(a→b) = a의 유효점(간격 3) 중 b 안으로 투영되고 z < 0.95·D_b(u)인 몫. φ_v = max(φ(r→v), φ(v→r)). 장면의 median_v φ_v > φ_rig이면 그 장면의 모든 판정은 ABSTAIN이고 릴레이는 꺼집니다. 뷰 단위로는 쓰지 않습니다(N7). 다른 가족은 φ_rig를 읽지 않습니다(코드와 같음).

### 3.3 Fix A 통계 (네 가족; §6.2에서 하나를 고름)

공통: Q = L(m̂, v), q = 좌표별 중앙값(Q), d_j = ‖q − c_j‖.

| 가족 | 규칙 | 격자 |
|---|---|---|
| **A-c0** 시뮬레이션 규칙 | n\* = argmin_{모형 있는 j} d_j. n\* = o → PASS, 아니면 FLAG. o 모형 없음 또는 모형 있는 객체 < 2 → ABSTAIN | 없음(기준 행; F1 탈락 예상) |
| **A-c\*** 논리곱 규칙 | ABSTAIN: \|Q\| < N_min, o가 모형 없음·넓음·잘림, P90‖Q − q‖ > γ·ρ_o + σ, 리그 불신. in_own = d_o ≤ β·ρ_o + σ. nearer = ∃ j ∈ J_o: κ·d_j < d_o. PASS = in_own ∧ ¬nearer. FLAG = ¬in_own ∧ nearer. 나머지 ABSTAIN | β {1.0, 1.25, 1.5} × κ {1.0, 1.25, 1.5} × σ {0.03, 0.05} × ρ_env {0.5, 1.0} × b_max {1 %, 5 %, ∞} × γ {2, 3, ∞} × φ_rig {0.12, ∞} = 648 |
| **A-v** 3D 투표 | R̃_j = R_j의 결정적 간격 부분표본(≤ 1 024점), Q̃ ≤ 4 096점. d_j(q) = min_{p ∈ R̃_j} ‖q − p‖. l(q) = argmin_j d_j(q)(그 최소 ≤ r_max일 때), 아니면 0. ov3d = \|{q : l(q) = o}\| / \|Q̃\|. plur = argmax_{j ≥ 1} n_j(동률 → 낮은 id; 모두 0이면 0). ABSTAIN: o 모형 없음 또는 \|Q\| < N_min. PASS = ov3d ≥ 0.5. FLAG = plur ∉ {0, o}. 나머지 ABSTAIN | r_max {0.2, ∞} |
| **A-h** 혼합 | vis = reproj의 n_valid / \|m\|. A-v가 FLAG면 FLAG. 아니면 vis ≥ 0.5일 때 overlap ≥ 0.5 → PASS, 아니면 ABSTAIN. vis < 0.5면 A-v의 상태 | ν = 0.5 고정 |

### 3.4 최종 선택과 배타

Fix A가 작용하는 뷰(L7):
- 범위 R, seq: **릴레이된 F 뷰**. 도달 불가 F 뷰와 리그 불신 장면의 F 뷰는 C0 Jacobi 라운드 2 출력을 그대로 쓰며 선택이 없습니다.
- 범위 R, jacobi(A·Ac 팔): F 전부.
- 범위 G·GN: 모든 비기준 뷰.

그 뷰의 객체 o마다:
- 후보 X = 그 뷰의 2차 출력(릴레이 출력, 또는 Jacobi 라운드 2 출력). S1 = 라운드 1 출력(c_ini만).
1. status(X) ∈ {PASS, ABSTAIN} → X.
2. 아니면(FLAG·EMPTY) status(S1) = PASS → S1.
3. 아니면 대체: **유지 = X(주)** / 사슬 마스크(ABc·Ac) / 빈 마스크(ABe).

배타와 기억:
- 고른 원 로짓을 객체별로 쌓고 채택 xcl `outs`(XCL_SHIFT 0.5, XCL_TAU_KEEP 0.5)를 그대로 돌립니다.
- 사슬 대체는 출력 해상도에서 안 +1 / 밖 −1024 로짓, 빈 대체는 −1024로 들어갑니다.
- 기억은 고른 출력의 1008 로짓·presence·obj_ptr로 `encode_memory_from_prediction`을 부릅니다. conf = 그 출력의 신뢰입니다.
- **사슬·빈 대체 객체는 기억이 되지 않습니다**(conf 거짓; 로짓은 X의 것을 넣고 게이트로 가림).
- Fix A가 작용하지 않는 팔(B-rep, B-obj)은 선택 없이 릴레이 출력을 그대로 씁니다.

### 3.5 Fix B 릴레이

도달 가능 여부는 기하만으로 정해지므로 디코딩 전에 계산합니다(S에서 시작해 hop ≤ θ_s 간선으로 BFS). 닿지 않는 F 뷰는 C0의 Jacobi 라운드 2 출력을 그대로 쓰고 "도달 불가"로 셉니다.

1. 𝒟 ← S. 원소 u마다 최종 출력의 원 로짓·presence·obj_ptr, Fix A 상태, 신뢰를 둡니다. 범위 R에서 S의 최종 출력은 C0 라운드 2 출력 그대로입니다.
2. E = {아직 안 푼 도달 가능 v ∈ F : ∃ m ∈ 𝒟, hop(m, v) ≤ θ_s}. E = ∅이면 멈춥니다.
3. v = argmin_E a_v(동률 → 카메라 자연 순서).
4. 후보 = hop(m, v) ≤ θ_s인 𝒟 원소를 π³ 중심 거리순(동률 → 자연 순서)으로 앞에서 K_search = 6개. 이웃 = 그중 신뢰 객체가 하나 이상인 앞의 3개.
5. 기억 = MemorySet([c_ini] + 이웃 기억). 객체별 게이트(`gate_mask`)는 지금 그대로입니다. 신뢰 아닌 객체의 열은 −inf이고 c_ini는 게이트하지 않습니다.
6. 이웃이 없으면 기억 = {c_ini}입니다. 라운드 1과 같은 경로이므로 출력 = 라운드 1 출력이며 "고아 뷰"로 셉니다. 어떤 객체가 모든 이웃에서 신뢰가 아니면 그 객체는 c_ini만 보며 "고아 객체"로 셉니다.
7. `decode_view(chunk = OBJ_CHUNK 8)` → Fix A 상태 → §3.4 선택 → xcl → PNG. 고른 출력의 기억을 인코딩해 v를 𝒟에 더합니다.

고정 규칙:
- θ_hop = θ_s(상수 하나). K = 3(라운드 2 k와 같음). K_search = 6.
- 두 번째 패스 없음. 라운드 1은 모든 뷰에서 그대로입니다.
- 기준 모형은 갱신하지 않습니다(표류 없음).
- 별 뷰 라운드 2는 릴레이 출력을 읽지 않습니다. 별 뷰 라운드 2의 후보는 지금처럼 모든 뷰의 라운드 1 출력입니다.
- 디코딩 수: F 뷰의 라운드 2 디코딩 하나를 릴레이 디코딩 하나로 바꿉니다. C0와 같습니다.

### 3.6 범위와 F 디코딩 방식

| 범위 | Fix A가 작용하는 곳 | S 뷰 | 역할 |
|---|---|---|---|
| **R** | F만(§3.4). S 뷰의 Fix A 상태는 릴레이 기억 신뢰에만 씀 | 라운드 2(reproj)와 출력이 C0와 바이트 동일 | **주(U2로 고정)** |
| G | 모든 뷰. 라운드 2 기억 신뢰 = Fix A 신뢰(reproj 교체), S 뷰에도 §3.4 선택 | 바뀜 | 측정 |
| GN | G + 선택 뒤에도 FLAG가 남은 S 뷰를 a_v 순으로 릴레이식 재디코딩(§3.5 이웃 규칙, 자기 제외). 재디코딩 출력은 FLAG 객체에만 **§3.4 선택 없이** 그대로 씀(상태·신뢰도 재디코딩 출력의 것). 이웃이 없으면 재디코딩하지 않음(L7) | 바뀜 | 측정 |

F 디코딩 방식:
- **seq(릴레이)**: §3.5.
- **jacobi(Fix A만)**: 지금 라운드 2 루프 그대로. F 대상의 후보 신뢰만 Fix A 신뢰로 바꾸고 §3.4 선택을 합니다. 기억 인코딩은 한 번 하고 conf만 바꿔 씁니다(`replace(view, conf=…)`).

**범위 R에서 F = ∅이면 Fix A를 계산하지 않습니다.** 출력과 비용이 C0와 같습니다.

### 5.3 H2·H3 판정 규칙 (L11; 서술, 주 팔을 바꾸지 않음)

- **P_good** = AB의 릴레이된 먼 쌍 중, 그 객체에 신뢰된 이웃 기억이 하나 이상 있고 그 이웃 기억이 맞는 쌍(이웃 출력의 covers = 자기, T06 정답으로 사후 판정).

- **"이웃 기억이 맞음"의 판정(코드가 정한 것을 등록, 2차 검토).**

## 6. 상수 선택 절차 (DEV-A + DEV-A′ + T06 개발만)

각 규칙은 그것이 고르는 데이터를 보기 전에 이 문서로 커밋합니다. DEV-B, DEV-B′, 키프레임(어떤 기준이든), CROOM 새 정답, ScanNet++는 고르는 데 쓰지 않습니다.

**DEV-A′(U1 승인).** 정의는 [stage1-dev-protocol.md](stage1-dev-protocol.md) §4를 따릅니다.
- DEV-A 프레임에서 기준을 다른 주석 카메라 r′로 돌린 집합입니다. 평가 카메라 = 나머지 둘. 객체 = r′에 있는 basic 객체.
- π³ 프레임 캐시는 그대로 씁니다. 장면의 자기 폴드 체크포인트를 씁니다.
- MUVOD에서 55–90° 쌍이 있는 유일한 도메인 내 설계 집합입니다(Blocks, Fencing, MartialArts, CBABasketball).
- 기준을 돌린 키프레임은 TEST로 보고 디코딩하지 않습니다.
- DEV-A′ 디코딩(C0와 팔)은 GPU이므로 카트 뒤입니다(D7). Step 1은 DEV-A′ **정답만** 쓰므로 호스트에서 바로 합니다. DEV-A′ 디코딩이 필요한 조건은 Step 2에서 씁니다.

### 6.4 Step 2 — θ_s (s\* 고정, 범위 R)
- 격자 Θ = {35, 40, 45, 50, 55, 60, ∞}(객체 기준 도). ∞ = 릴레이 꺼짐 = 범위 R에서 C0.

- DEV-A′: 유한 θ마다 AB를 두 회전에 디코딩합니다.
  - **C0 채움 규칙(2차 검토).** 평가 뷰가 θ 밖(F)에 하나도 없는 장면은 디코딩하지 않아도 되며, 그 장면은 C0 행으로 채웁니다. 근거는 I2(범위 R에서 S 뷰 출력은 C0와 바이트 동일)이고, Z-I2가 통과한 뒤에만 씁니다.
  - 평가 뷰가 F에 있는 장면이 빠진 실행은 미완이므로 멈춥니다.
  - 채운 장면은 `step2.json`에 기록합니다. DEV-A θ < A_E 전체 디코딩과 Step 2b에도 같은 규칙을 씁니다.
  - 어느 장면을 디코딩할지는 Step 0 `angles.json`(입력만)으로 정합니다. θ 55·60은 넓은 4장면 이하이고, 그보다 작은 θ에서는 더 많을 수 있습니다(§9).
- 허용 θ ⇔ 모두:
  - T06 wrong_all(θ) ≤ 28(C0보다 나쁘지 않음).
  - DEV-A′ 모든 쌍 ΔJ&F CI 하한 > −0.003, −0.01 아래 장면 없음.
  - θ를 넘는 DEV-A′ 쌍의 ΔJ 점 추정 ≥ 0. 점 추정은 장면 군집 부트스트랩(쌍 → 뷰 → 장면, 10 000회, seed 0)의 점 추정입니다. 그런 쌍이 없으면 이 조건은 공허(만족)입니다.
  - ∞는 AB(∞) = C0이므로 T06 wrong_all = 28이고 DEV-A′ 조건은 공허입니다. 그래서 늘 허용입니다.
- J\* = 허용 θ 중 T06 J_all 최대. 후보 C = {허용 θ : J_all(θ) ≥ J\* − 0.01}.
- C를 큰 θ부터 보며 처음 **DEV-A 안전**인 것을 고릅니다.
  - θ ≥ A_E: DEV-A 평가 뷰가 F에 없음(`angles.json`). 그리고 Z 단계(§6.3b)가 `runs/zcheck.json`에 통과로 있어야 합니다. θ ∈ [A_E, A_all)이면 그 θ의 Z-R(경우 Z 변형)도 통과여야 합니다. 없으면 Step 2는 고르지 않고 멈춰 필요한 검사를 적습니다(`need_zcheck`).
  - θ < A_E: 그 θ에서만 DEV-A 전체 디코딩. ΔJ&F CI 하한 > −0.003 ∧ −0.01 아래 장면 없음. 없으면 Step 2는 멈춰 필요한 디코딩을 적습니다(`need_devA`).
- **θ_s\* = ∞가 되는 경우(코드가 정한 것을 등록, 2차 검토).** C 안에 DEV-A 안전인 θ가 하나도 없으면 θ_s\* = ∞입니다. C 밖의 θ로 넘어가지 않습니다. (허용 θ가 없는 경우도 같은 규칙이지만, ∞가 늘 허용이므로 실제로는 생기지 않습니다.)
- 고른 값이 ∞이면 릴레이를 닫고 G1 대체 (b)로 갑니다(§7.3).
- `need_devA`·`need_zcheck`가 남은 `step2.json`은 미완입니다. Step 2b, Step 3, 판정(§7)은 미완 Step 2를 θ_s\* = ∞로 읽지 않고 멈춥니다.

### 6.5 Step 2b — 통계 교체 검사 (T06)
- θ_s\* = ∞이면 Step 2b는 없습니다.
- s\*가 아닌 가족마다 F1–F3를 만족하는 최선 후보(§6.2 순서; A-c\*는 c_best)를 θ_s\*에서 AB로 T06에 디코딩합니다.
- 교체 조건(T06) ⇔ J_all이 s\*보다 ≥ 0.02 높음 ∧ wrong_all이 더 적음. 문턱을 높게 둔 이유는 T06이 한 프레임이기 때문입니다.
- **여러 가족이 조건을 만족하면(코드가 정한 것을 등록, 2차 검토)** J_all이 가장 높은 것, 같으면 wrong_all이 적은 것, 같으면 가족 순서(A-v, A-c\*, A-h, A-c0)로 s′ 하나를 고릅니다.
- **s′의 도메인 내 재검사(2차 검토).** 교체는 s′가 아래를 모두 통과할 때만 합니다.
  1. DEV-A′: AB(s′, θ_s\*)를 두 회전에 디코딩(§6.4 C0 채움 규칙 같음). §6.4의 DEV-A′ 조건 세 개를 θ_s\*에서 만족(모든 쌍 CI 하한 > −0.003, −0.01 아래 장면 없음, θ_s\*를 넘는 쌍 ΔJ 점 추정 ≥ 0).
  2. θ_s\* < A_E이면 §6.4의 DEV-A 안전 검사를 s′로 다시 합니다.
- 검사는 고른 s′ 하나에만 합니다. 통과하지 못하면 교체하지 않으며, 다음 가족으로 넘어가지 않습니다.
- 교체되면 주 팔 = AB(s′, θ_s\*)입니다.
- Step 1b와 Step 2는 다시 하지 않습니다.
