# S1-E2 사전 등록 — G-det 관문: 동결 기준선 F0의 뷰에서 예시 검출이 정답 객체를 후보로 내는가

> 2026-09-10. [stage1-plan.md](stage1-plan.md) §5 S1-E2(관문 문안은 v2에서 등록, 분모는 F0 동결 뒤 §10 "분모 갱신"으로 19쌍 기준 ≥11).
> 사용자 결정(b): G-det의 후보 생성기 = **박스 예시와 내부 점 예시 두 프롬프트의 후보 합집합**([stage1-E2-0c.md](stage1-E2-0c.md) §4).
> 층: 탐색. 이 실험은 측정만 하며(시드 폴더를 쓰지 않음), 통과하면 `run_seed_det.py`(시드 writer)와 연결 규칙을 다음 등록에서 정합니다.

## 1. 알려진 사실
- 스파이크 E2-0/0′/0″: 동결 SAM 3 검출기에 c_ini 예시 토큰을 다른 뷰의 `visual_prompt_embed` 슬롯으로 주입하면 정상 쌍(N0, ≥2k px)에서 정답 객체 IoU≥0.5 후보가
  박스 17/20·점 18/20, 합집합 19/20(핀홀 보조 19/20) — 대조군(예시 없음) 0/20. 박스와 점은 서로 다른 쌍에서 실패함. 마스크 토큰은 불가.
- F0(동결, `MVSeed/runs/F0.json`): 41쌍 = 빈 시드 3(+ raw_J=0 포함 6)·자리 틀림 38; **정답 ≥2,000 px 19쌍(핀홀 16·반구 3)**, <2,000 px 22쌍. N0 = 623쌍. 정답 없는 행 132(= 796 − 664).
- 검출기 입력은 1008×1008 리사이즈이므로 원본 2,000 px 객체는 특징 격자(72×72)에서 약 0.6칸 — <2k px 구간은 보고만(등록 문안).

## 2. 측정
장면 17개 × (c_ini + 주석 카메라 2대) × 객체(census `seed_ids_c_ini`, c_ini 첫 프레임에 있는 basic 객체) = **796행**(정답 있음 664 = F0 41 + N0 623, 정답 없음 132).
1. c_ini에서 객체마다 두 프롬프트 — `box`(꽉 맞는 박스), `pts`(박스 + 마스크 내부 양성 점 8; E2-0″와 같은 규칙·상수) — 의 예시 토큰을 포획(E2-0″ 코드 그대로, 패키지 무수정).
2. 각 주석 카메라에서 두 토큰을 각각 주입해 검출(텍스트 "visual", 후보 규칙 = 패키지: prob>0.5 후 NMS 0.1). **합집합** = 두 실행의 후보를 그대로 합쳐 prob 내림차순(실행 간 중복 제거 없음; 중복은 순위에 무해 — IoU 최대 후보의 순위는 높은 쪽 복사본으로 정의).
3. 행마다 기록: gt_px, 실행별 후보 수, 합집합 후보 수(그대로 / 실행 간 IoU>0.5 중복 제거 후, 보고용), 정답과 IoU 최대 후보의 IoU·순위·prob·출처, 1위 후보 IoU, 실행별 최고 IoU, F0/N0/정답 없음 소속, F0 종류(빈/자리 틀림), 크기 구간, 리그.
정답은 오프라인 측정에만 씁니다. 스크립트 `MVSeed/gate_det.py`, 결과 `MVSeed/runs/e2_gate.json`.

## 3. 판정 규칙(고정; 등록 문안 + F0 분모)
| 항목 | 모집단 | 기준 |
|---|---|---|
| **관문 1** 존재 | F0 ∩ 정답 ≥2,000 px (19쌍) | IoU≥0.5 후보 존재 **≥55% → ≥11/19** |
| 관문 1′ 핀홀 | 그중 핀홀 16쌍 | 존재 **≥8/16** (등록 문안 8/18을 F0 분모로; 반구가 3쌍뿐이라 관문 1 통과는 1′를 함의 — 보고용) |
| **관문 2** 순위 | 관문 1에서 존재하는 쌍 | IoU 최대 후보의 합집합 순위 **중앙값 ≤3** |
| **관문 3** 환각 | 정답 없는 132행 | 합집합 후보 ≥1인 행 **≤10% → ≤13/132** |
| 보고만 | F0 ∩ <2,000 px 22쌍; N0 623쌍 | 존재율·순위 분포(N0는 정상 쌍의 기준선); 실행별(박스/점) 존재; 리그별 |

- 관문 1·1′·2 통과 → G-det **진행**(다음 등록: 시드 writer `run_seed_det.py` + 연결 규칙, E5 신호).
- 관문 1 또는 2 미달 → **G-det 폐기**(검출–연결은 G-corr/G-geo/G-gs 위치 + 1프레임 프롬프트만). 1′만 미달이면 진행하되 반구 한정 이득으로 표기.
- 관문 3만 미달 → G-det 진행하되 **빈 G0 채움 금지**: SeedVote에서 G-det 후보는 G0이 비어 있지 않은 (뷰, 객체)의 교체에만 쓰고, 빈 G0 채움 규칙(§4 강화 조건)의 후보에서 제외. 환각률은 E5의 S1/S2 신호로 걸러지는 비율과 함께 보고.
- 점수 임계·NMS·프롬프트 상수는 위에 고정. 데이터를 본 뒤 바꾸지 않음.

## 4. 예측
- 관문 1: **11~14/19**(58~74%) — 통과하되 여유 없음. 핀홀 9~12/16 통과, 반구 3쌍은 0~2.
- 관문 2: 순위 중앙값 **1~2** 통과.
- <2k px 22쌍: 존재 **30~50%**(1008 입력에서 20 px 남짓) — G-det만으로 소형 봉투(+1.25)의 절반 이하.
- N0: 존재 80~90%, 순위 중앙값 1; 박스 단독 < 합집합 (+2~5%p).
- 관문 3: **25~45% → 미달 가능성 큼**(같은 종류 개체·환경 영역이 다른 뷰에 있으면 검출됨) → "빈 G0 채움 금지" 조건부 진행이 가장 유력한 결과.
