# S1-E3 사전 등록 — G-corr: **DINOv2 대응 프롬프트**로 F0 뷰에서 객체 위치를 찾는다

> 2026-09-12. [stage1-plan.md](stage1-plan.md) §5 S1-E3. 층: 탐색. 학습 없음 — DINOv2는 공개 가중치 추론만(계획 §0 확정).
> **관문은 계획에 이미 등록된 "E2와 같은 관문"을 그대로 씁니다**(아래 §3). 이 문서가 새로 고정하는 것은 **방법의 상수**뿐입니다.
> 사용자 결정(2026-09-12): E3 → E6 → E6′ → E7 체인으로 진행.

## 1. 알려진 사실 (후보 J를 보기 **전에**)

- **같은 모집단에서 이미 측정된 것**: 검출 경로 [E2](stage1-E2.md) 존재 **9/19**(핀홀 6/16, 반구 3/3), 순위 중앙값 1, 환각 **129/132 = 98%**;
  기하 세 팔 [E4a](stage1-E4a.md) 4/16 · [E4b](stage1-E4b.md) 1/16 · [E4c](stage1-E4c.md) 0/16; 검출 ∪ 기하 = **7/16 < 8**.
- **모집단은 동결된 그대로**: F0 41(자리 틀림 38 + 빈 3), F0 ∩ ≥2,000 px **19**(핀홀 16 · 반구 3), F0 ∩ <2k 22, N0 623, 정답 없는 132행. 합 796.
- **G-corr는 계획의 다섯 생성기 중 유일하게 시도되지 않은 팔**입니다(G0 ✅ · G1 ✅ · G-det ❌ · G-geo ❌ · G-gs ❌).
- **문헌이 예고하는 위험**([mvimage-seg-survey.md](mvimage-seg-survey.md)): 시점차 135\~180°에서 세그먼트 대응이 무너집니다(SegMASt3R 표, AUPRC 17.0). F0 쌍은 정확히 광기선 쪽에 몰려 있습니다.
- **해상도 위험(E4b의 교훈)**: DINOv2는 패치 14 px입니다. 기본 518×518이면 37×37 = 1,369 패치뿐이고, 1920×1080에서 2,000 px 객체는 화면의 0.1%라 **패치 1\~2개**에 불과합니다. 그래서 이 팔은 **입력 해상도를 올려서** 돌립니다(§2). 다만 G-corr가 만들어야 하는 것은 **마스크가 아니라 위치**이고 분할은 SAM 3가 하므로, 객체 안에 점 하나를 찍을 수 있으면 충분합니다 — 이것이 E4b(마스크를 직접 옮겨야 했음)와 다른 점입니다.
- 배관 사실: `scsam3`·`scgeo:pi3`·`3dgs` 어느 이미지에도 `transformers`가 없어 **별도 이미지 `scgeo:dino`**(DINOv2 가중치 내장, 오프라인)를 씁니다. 계획 §6의 "G-geo·G-corr 공용 프롬프트 파일" 구조 그대로: 대응 패스가 점을 JSON으로 쓰고, SAM 3 패스가 그것을 읽습니다.

## 2. 방법 (상수는 실행 전에 코드에 고정)

`MVSeed/corr/dino_prompt.py`(컨테이너 `scgeo:dino`) → `MVSeed/corr/e3_segment.py`(컨테이너 `scsam3`).

1. **모델**: `facebook/dinov2-large`(ViT-L/14, Apache-2.0). DINOv3는 게이트 라이선스라 제외(계획 §3).
2. **입력 해상도**: 종횡비 유지, **긴 변 1,036 px**(74 패치), 양변을 14의 배수로 내림, `interpolate_pos_encoding=True`. 마지막 층의 패치 토큰을 L2 정규화해 씁니다.
3. **기준 서술자(프로토타입)**: c_ini의 정답 마스크 안에 **패치 중심이 드는** 토큰들의 평균을 L2 정규화. 마스크가 작아 드는 패치가 없으면 마스크 무게중심에서 특징 지도를 **쌍선형 표본화**해 씁니다.
4. **유사도 지도**: 대상 뷰의 모든 패치 토큰과 프로토타입의 코사인 → 원본 해상도로 쌍선형 업샘플.
5. **후보 K = 5**: 비최대 억제 반경 **3 패치**로 뽑은 상위 5개 극대점. 각 극대점이 **양성 점 하나**입니다. 후보 점수 = 그 지점의 코사인.
6. **분할**: 후보마다 **(카메라, 객체, 후보) 단위의 단일 객체·단일 프레임 SAM 3 세션**에 `add_prompt(points=[peak], labels=[1])`. 세션이 섞이지 않도록 후보끼리 한 세션에 넣지 않습니다(겹침 억제가 비교를 오염시킴).
7. **후보 존재 조건**: 극대점의 코사인 **≥ τ_sim = 0.5** 이고 분할 마스크가 비어 있지 않을 것. τ_sim은 이 프로젝트가 계속 쓰는 0.5(계획 §4, 실패 정의 J<0.5와 같은 값)이며 **데이터를 보기 전에 고정**합니다. 임계 민감도 곡선은 보고만.
8. 모집단·채점은 E2·E4와 **같은 796행, 같은 코드 경로**(`MVSeed/gate_det.py`의 집계)를 씁니다.

## 3. 판정 규칙 — 계획 §5 S1-E3 행의 "E2와 같은 관문" 그대로

- **관문 1(존재)**: F0 ∩ ≥2,000 px **19쌍 중 정답과 IoU ≥ 0.5인 후보가 있는 쌍 ≥ 11**(= 55%; 핀홀 분해는 ≥8/16).
- **관문 2(순위)**: 정답과 IoU 최대인 후보의 **순위 중앙값 ≤ 3**.
- **관문 3(환각)**: 정답 없는 **132행에서 후보 ≥1인 비율 ≤ 10%**.
- 셋 다 통과 → G-corr를 진행(E6의 후보 집합에 편입). 하나라도 미달 → **G-corr 폐기**. 그러면 계획의 **다섯 생성기가 전부 등록된 규칙으로 닫힙니다**.
- **보고만**(중단 규칙 없음): F0 <2k 22쌍, F0 반구, N0 623(크기 구간별 존재·순위), 장면별, 시점차(기준↔대상 각도)별, τ_sim 민감도, **E2 통과 쌍과의 겹침**, 그리고 E2 ∪ E4 ∪ E3 합집합의 관문 16쌍 값.

## 4. 예측

1. **관문 1 미달: 존재 6\~11/19**. 근거: 광기선에서 의미 대응이 무너진다는 문헌, 그리고 F0가 작은 객체에 몰려 있다는 우리 측정.
2. **관문 2 통과: 순위 중앙값 1\~2**. 맞히는 경우에는 최상위로 맞힐 것(프로토타입 유사도는 정답 객체에서 가장 높음).
3. **관문 3 크게 미달: 환각 60\~90%**. 코사인 ≥0.5는 배경에서도 흔히 넘습니다. 다만 검출기(98%)보다는 낮을 것.
4. **N0 존재 70\~90%** — 정상 쌍은 시점차가 작고 객체가 큽니다.
5. **크기 의존이 E2보다 가파를 것**: <2k 존재율이 ≥2k의 **절반 이하**. 패치 해상도가 원인.
6. **E2와 크게 겹칠 것**: E3가 맞히는 F0∩≥2k 쌍의 **≥70%가 E2도 맞힌 9쌍 안에** 들 것. 둘 다 외형 경로이므로. 합집합(검출 ∪ 기하 ∪ 대응)도 **16쌍 중 8 미만**에 머물 것 — 이것이 사실이면 **"위치를 만드는 세 가족(외형 검출·기하·외형 대응)이 모두 F0에서 닫힌다"**가 확정됩니다.
