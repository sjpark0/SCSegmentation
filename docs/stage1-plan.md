## 2. 문제 정의와 채점 규약 (1단계 전용)

**입력.** 장면의 `start_frame` 시각에 찍힌 N장(카메라 9~46대) + 기준 뷰(c_ini) 한 장의 객체 마스크. **기준 뷰 마스크는 항상 주어진다고 가정**하며(사용자 확정 09-10) 그 출처 — 정답, SAM 대화형, 수작업 — 는 방법과 무관합니다. 문제는 오직 "그 마스크로 나머지 뷰를 어떻게 분리하는가"이고, 이 계획과 벤치마크에서는 MUVOD 정답(basic 객체 집합)을 씁니다 — 기존 분석(상한 측정·실패 해부)과 같은 전제.
**출력.** 다른 카메라들의 객체별 마스크. **이 계획에서 교체 대상은 주석 카메라 2대(c_ini 제외)뿐**이고, 나머지 뷰는 본류의 G0 시드를 그대로 씁니다(P5 §6 권고·경로 1 차단; 비채점 뷰 교체는 별도 등록).

| 항목 | 규약 |
|---|---|
| 모집단 | **비기준·정답 있음 664쌍**(basic 집합)이 모든 관문의 분모. 정답 없는 132행(그 카메라에 객체 없음)은 별도 표 — 환각(빈 정답에 비어 있지 않은 시드)을 여기서 잼 |
| 1차 지표 | **시드 J**(마스크 IoU, `MVSeed/score_seeds.py`, `eval/eval_jf.py`와 같은 정의). 짝지은 ΔJ(후보 − G0), 장면 클러스터 부트스트랩 95% CI(seed 0, 10,000) |
| 보조 지표 | 시드 F, 실패 수(J<0.5), 경계 구간 [0.4, 0.6) 이동 수(현재 27쌍), 크기 구간별(<2k / 2k~10k / ≥10k px), 리그별(핀홀 13 / 반구 4), 장면별 최저, 쌍둥이 객체 장면(Blocks·CBABasketball·MartialArts, 실패 7쌍) 분리 |
| 통계 | 쌍 수준(664)에서 클러스터 부트스트랩 CI + Wilcoxon(비동점 ≤22면 정확, 그 위는 정규 근사); 장면 수준(17)은 보고만 |
| 정답의 용도 | c_ini 정답: 프롬프트와 후보 검증(S2·S3)에 사용(주어진 입력). 채점 카메라 정답: 오프라인 측정에만. 카메라 자세 파일: 진단·감시에만 |
| 최종 확인 | 본류 `--seeds-from` 훅으로 2단계를 돌려 **MUVOD basic J&F³**(21프레임, 17장면) — 사전 등록 뒤에만(§5 E7) |
| 쓰지 않는 것 | c_ini 첫 프레임에 없는 객체(73개, 어떤 방법도 0) |

(논문용 벤치마크 규약 — "MUVOD 한 프레임 규약", 유형별 분리 보고, 장면 단위 ID 매칭 — 은 이 계획의 판정과 무관하므로 ROADMAP의 논문 계획으로 옮깁니다. 유형 라벨은 크기 구간만 자동이고 환경 객체·가림은 수작업이 필요합니다.)

## 3. 후보 시드 생성기

분할 모델은 전부 **SAM 3(동결)**. 후보의 위치를 만드는 부품은 §0의 해석에 따릅니다.

| 생성기 | 무엇 | 왜 (근거) | 구현 상태 | 위험 |
|---|---|---|---|---|
| **G0 현행** — 번호 순 유사동영상 SAM 3 전파 | 대조군이자 기본값 | 비교 기준 | ✅ `MVSeed/run_seed.py --order index` (본류와 시드 면적 일치 확인) | — |
| **G1 순서 변형** — `reverse`, `ref_outward` | 인접 시점 차를 줄인 사슬 | 실패가 특정 전이에 뭉침(headroom §3.2) | ✅ E1 완료 — `reverse`만 후보(F0 5쌍 회복, N0 무손실), `ref_outward` 탈락 | 봉투가 작음: 비반구·거리≤3 실패 11쌍 전부 고쳐도 +0.3~0.5 |
| **G-det 검출–연결** | c_ini 마스크를 **예시 프롬프트**로 각 뷰에서 같은 개념의 후보를 검출하고 기준 객체와 연결해 시드로 | 검출은 뷰마다 독립으로 자리를 잡으므로 격자 정렬 가정을 쓰지 않음 → "자리 틀림" 38쌍을 겨냥. 문헌: InsDet 기초선(SAM 제안+DINO 매칭), Re-Prompting SAM 3, ViewSAM의 검출→연결→재프롬프트 | ⬜ **실현성 스파이크 필요(E2-0)**: 동결 패키지는 예시를 같은 이미지에서만 씀(§1.2). 단일 GPU 프로세스 안에서 `detector._encode_prompt`를 감싸 c_ini 박스의 예시 특징을 다른 뷰의 `visual_prompt_embed` 슬롯에 주입하는 서브클래스(패키지 무수정)를 시험. 실패하면 G-det 폐기 | 주입 경로가 학습 분포 밖일 수 있음; 같은 개념의 다른 인스턴스(쌍둥이 객체) 연결; 환경 객체는 개념이 모호; 2,000 px 미만 검출 여부 미지수. 텍스트 프롬프트(명사구 있는 객체만)는 진단 팔로만 |
| **G-geo 기하 투영** | 첫 프레임 N장 → 비보정 기하 모델 → c_ini 마스크를 3D로 올려 각 뷰에 워핑·재투영 → 투영 마스크, 또는 그것으로 만든 점·박스로 SAM 3 1프레임 세션 분할 | 자세가 있을 때 "1뷰 마스크→전 뷰 워핑"이 장면별 학습법보다 높음(SPIn-NeRF: OR-NeRF 95.4 / View-consistent Object Removal 94.3); MUVOD 정답 제작 절차와 같은 형식 | ⬜ 별도 도커 이미지(호스트 자원 충분: GPU 48 GB 유휴·RAM 125 GB·디스크 960 GB) + 캐시. **모델은 E4 등록 전에 하나로 확정**(라이선스 우선이면 MapAnything-apache, 무순서 리그 우선이면 π³) | **핀홀 13장면 한정**(반구는 어안); 무질감·반사(Welder)·유리(CoffeeMartini); 리그 입력에서의 붕괴(Rig3R 보고) 재현 여부; 봉투 +0.50 |
| **G-gs 3DGS 리프팅·가상 궤적** | 첫 프레임 N장 → 포즈(VGGT/MASt3R-SfM 또는 COLMAP) → 정적 3DGS(첫 프레임만) → **(a) 리프팅**: c_ini 마스크를 가우시안에 올려(FlashSplat식 닫힌 형, 학습 없음) 각 카메라로 렌더 → 시드 또는 SAM 3 1프레임 프롬프트; **(b) 가상 궤적**: c_ini→각 카메라 사이를 가상 뷰로 렌더한 매끄러운 유사동영상 위에서 **현행 SAM 3 전파(G0)** 실행 | (a) 렌더링이 가림·다중뷰 합의를 처리하고 마스크 그대로 리프팅이라 환경 객체 보존에 유리(동향조사 §3.1); 같은 계열이 MUVOD 3D 벤치마크 최상위(Gaussian Grouping 78.8). (b) 진단한 실패 원인(인접 프레임 가정 위반)을 SAM 3를 건드리지 않고 **입력 쪽에서** 맞춤(Seed2GS·SAGOnline 구조) | ⬜ 별도 컨테이너(3DGS 학습기), 장면당 학습 수 분; 포즈 캐시는 G-geo와 공유 | 3DGS 품질이 곧 상한(LUDVIG·SANeRF-HQ): 9~13대 직선 리그는 희소; 핀홀 13장면 한정(어안 제외), MATF는 MUVOD 3D 벤치마크에서 복원 불량으로 제외된 전례; 작은 객체는 렌더 해상도 한계; 가상 뷰의 렌더 아티팩트가 전파를 오도할 수 있음; 봉투 +0.50(G-geo와 같은 쌍) |

**실현 가능한 "검출–연결"의 형태.** 위치(G-det 후보·G-geo 투영·G-corr 매칭)가 정해지면 **SAM 3 트래커의 1프레임 세션에 점·박스 프롬프트**(`add_prompt(points, point_labels, obj_id)`; 박스는 라벨 2/3 두 점)로 분할합니다. N뷰 유사동영상 안에서 검출 팔을 돌리면 시간 소거(hotstart, 8뷰 연속 미매칭 제거)가 작동하므로 **뷰마다 1프레임 세션**으로 합니다.

**2단계 공급.** 선택된 시드는 본류 `runMVSeg.py`의 `masks_spatial` 자리에 `--seeds-from <MVSeed_폴더>` 훅으로 들어갑니다. 폴더에 없는 (뷰, 객체)는 **결손이 아니라 G0 유지**(`AddReferenceMask`·`PropagateAcrossViews`는 그대로 돌려 폴백 확보). 시드가 빈 객체는 지금처럼 0 마스크로 등록해 되찾기 경로(direction-cini §3)를 보존합니다. 2단계 입구의 재예측·겹침 제거·이웃 채널은 손대지 않습니다. 단, 프레임 0 **출력**은 `--frame0-seed`로 시드를 그대로 씁니다(E0″ +0.030점, 프레임 1~20 불변).

## 4. 검증·선택 — SeedVote

후보 집합 {G0, G1, G-det, G-geo, G-corr}에서 주석 카메라 2대의 (뷰, 객체)마다 신호를 계산하고, **기본값은 G0**, 교체는 조건을 통과할 때만.

| 신호 | 정의 | 잡는 것 | 한계 |
|---|---|---|---|
| S1 후보 간 일치 | 후보 마스크끼리 IoU | 서로 다른 원리가 같은 자리에 놓으면 오배치 확률 낮음(추정, 측정 전) | 공통 실패(작은 객체를 모두 놓침); G-det·G-corr는 둘 다 외형 기반 |
| S2 앵커 투영 일치(핀홀만) | c_ini 정답의 기하 투영(포인트맵 워핑 또는 3DGS 렌더)과 후보의 IoU | 자리 틀림을 직접 검사하는 **유일한 비외형 신호** | 기하 실패 뷰에서 무의미 → 그 뷰는 미사용 |
| S3 되돌림(선택) | 후보를 프롬프트로 [v, c_ini] 2프레임 세션 → c_ini 정답과 IoU | 동점 해소 | 쌍둥이 객체에서 거짓 통과; 비용 |
| S4 외형 | c_ini 프롬프트의 SAM 3 객체 포인터와 후보 포인터의 코사인 | 순서·기하와 무관한 "같은 물체인가" | 마스크 프롬프트 포인터와 추적·검출 포인터의 분포가 같다는 보장 없음 → E5에서 정상 619쌍의 코사인 분포를 먼저 보고 정의역을 등록. 빈 G0에는 정의되지 않음 |

**임계값 — 지금 고정(등록값).** τ_disagree = τ_agree = τ_geo = τ_overlap = **0.5** (실패 정의 J<0.5와 같은 값). 후보 출력을 보기 전에 정한 값이므로 데이터 본 뒤 결정이 아닙니다. 장면 leave-one-out은 **민감도 분석(탐색)**으로만 표에 싣고 E6·E7 판정에는 쓰지 않습니다(MUVOD에 검증 분할이 없어 LOO τ는 시험 집합 정답으로 파라미터를 맞추는 것이 됨).

**선택 규칙(사전 등록 문안).**
- G0이 비어 있지 않은 경우: 어떤 후보가 (i) G0과 IoU < 0.5로 크게 다르고, (ii) 다른 후보 하나 이상과 IoU ≥ 0.5로 일치하거나 S2 ≥ 0.5이며, (iii) S4가 G0보다 높을 때만 교체.
- **G0이 빈 경우(실패 45쌍 중 7쌍)**: (i)·(iii)이 자동 성립하므로 강화 조건 — 핀홀: S1 둘 이상 일치 **그리고** S2 ≥ 0.5; 반구: S1 셋 이상 일치 — 에서만 채움. 아니면 빈 채로 두어 되찾기 경로를 보존.
- **겹침 기각(P5 경로 2)**: 후보가 같은 뷰의 다른 객체 G0 마스크와 IoU > 0.5면 기각.
- **금지**: G0이 비어 있지 않은 (뷰, 객체)를 어떤 판정으로도 0 마스크로 바꾸지 않는다. **donor 금지** — donor = 다른 카메라의 *예측* 마스크를 `add_prompt`로 명시 조건화하는 것(P5 RepairSeeds 방식); 전파기 내부 기억·되돌림 검증 세션은 해당 없음.
- 정답 없는 132행: 비어 있지 않은 시드 수가 G0보다 늘지 않아야 함(환각 금지).

## 8. 위험과 열린 질문

- **G-det 실현성**: 동결 API에 교차 이미지 예시 경로가 없음 → E2-0이 첫 관문. 실패하면 "검출–연결"은 G-corr/G-geo 위치 + 1프레임 프롬프트 형태만 남음.
- **G-gs**: 희소 리그(9~13대)에서 3DGS 복원 품질; 가상 궤적의 렌더 아티팩트가 SAM 3 전파를 오도할 위험; 학습 시간(장면당 수 분)과 별도 컨테이너.
- **G-geo**: 기하 이미지 호환(torch/CUDA), 리그 붕괴(Rig3R 보고) 재현 여부, 반사·유리, 어안 4장면 불가, 라이선스(연구용 무관; 이전 시 MapAnything-apache).
- **대리 지표**: 원시 시드 J → 최종 J의 관계는 미측정(E0가 회귀 추가); G-det·G-geo 마스크는 G0과 통계가 달라 288 재예측에서 어떻게 변할지 모름(E6′).
- **검정력**: 17장면 수준에서 최소 검출 효과 ≈ +1.0점; 측정 근거 범위 +0.2~+0.8이면 E7 1차가 쌍 수준에서만 유의할 수 있음 — 사전에 그렇게 적음.
- **회귀는 인과가 아님** — 원래 어려운 (카메라, 객체)는 시드를 고쳐도 안 오를 수 있음(E7이 답).
- **288 격자 인공물(E0′·E0″ 확정)** — 프레임 0은 `--frame0-seed`로 회수(+0.030점). 나머지는 **매 프레임** 디코더 격자의 손실: 기준 카메라 <2k px가 프레임 0 0.822 → 프레임 1~20 0.632. 봉투 +0.41(<2k)~+0.66점(<10k) — 이 계획의 측정 근거 범위와 같은 자릿수. 해법은 모델이 아니라 **유효 해상도**(작은 객체 주변 크롭 추적)이며 2단계 변경이라 **별도 등록(S2-R1) 후보**.
- **재예측이 시드를 깎음** — 2단계 입구 패치는 이 계획 밖(E7의 이웃 노출 판정이 −0.2점 이하일 때 별도 등록).
- **논문 서사** — "SAM 3 기반, 학습 없는 다중시점 시드 생성 + 위치 기준 검증"; SAM 2는 진단 절에서만.
