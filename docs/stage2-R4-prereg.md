# S2-R4 사전 등록 — 크롭 창의 **배율**(`crop_scale`) 절제: 벽은 면적이 아니라 확대율이었다

> 2026-09-11. [stage2-R3.md](stage2-R3.md)가 남긴 진단의 직접 후속. 층: 2단계 확정(17장면 MUVOD basic). 사용자 지시로 진행.
> 대조군은 **이미 측정된 헤드라인** `SegMaskSam3XW1CGPS4MFsCs10kG2`(basic **91.015** / complete 86.4). 다시 돌리지 않습니다.

## 1. 알려진 사실 (전부 헤드라인의 매니페스트에서 재측정, GPU 0)

크롭 창은 `side = clamp(ceil(scale × max(박스 w, h)), min_side, min(H, W))`, 정사각, 1008로 리사이즈 → **확대율 = 1008 / side**. `scale`은 S2-R1에서 4로 고정된 뒤 **한 번도 절제된 적이 없습니다**(`min_side` 256도 같음).

- **대상 349쌍**(15장면; 2장면은 채점 카메라에 <10,000 px 프롬프트 객체가 없음), **채택 278 / 되돌림 71**.
- **되돌림 사유: 확대율 61 · IoU 9 · 창 가장자리 1.** 즉 되돌림의 **86%가 확대율 규칙**(zoom < 1.2) 하나입니다.
- 확대율 분포(scale 4): 중앙값 **2.21**, 10분위 1.01, 90분위 3.94, 최소 0.58.
- 박스 최장변: 중앙값 **114 px**, 90분위 249, 최대 1,299.
- 창을 정하는 것: 4×최장변 **256쌍** · 256 바닥 **72쌍** · 이미지 크기 클램프 **21쌍**. (바닥에 걸린 72쌍은 `scale`을 줄여도 창이 그대로입니다.)
- **반사실 계산(확대율 규칙에 대해서는 정확함 — 창을 줄이면 확대율은 절대 내려가지 않음)**:
  `scale 2`이면 확대율로 되돌려진 61쌍 중 **57쌍**이 1.2를 넘습니다(나머지 4쌍은 이미지 클램프에 걸림). `scale 3`이면 **34쌍**.
  현재 채택된 278쌍 중 확대율 규칙에 새로 걸리는 쌍은 **0**입니다.
- **봉투**: 그 57쌍의 현재 J&F 평균 **0.841**(중앙값 0.880) → 완벽해지면 **+0.89점**. 별도로 이미 채택된 278쌍도 확대율 중앙값이 **2.21 → 3.94**로 올라갑니다(그쪽 완벽 봉투 +2.83점; 주장하지 않고 보고만).
- 확대가 무엇을 사는지에 대한 기존 측정([stage2-R1.md](stage2-R1.md)): 기준 카메라의 <2,000 px 36쌍에서 프레임 1\~20 J **0.637 → 0.842**.
- S2-R3가 확정한 것: **벽은 "면적 10,000"이 아니라 "박스 최장변 210 px"**. 면적 문턱만 올리면 신규 대상의 79%가 확대율로 되돌려집니다.

## 2. 방법 (상수는 실행 전에 고정)

- 두 팔: **`--crop-scale 2`** → `…Cs10kS2G2`, **`--crop-scale 3`** → `…Cs10kS3G2`. 그 밖의 인자는 헤드라인과 **글자 그대로 같습니다**(`--xview-window 1 --xview-mode C --xview-gate --xview-ptr --xview-tpos-shift 4 --ref-cam muvod --frame0-seed --crop-small 10000 --crop-gate v2`).
- **배관 수정(실행 전, 이 등록의 일부)**: `crop_suffix`가 기본값이 아닌 `scale`·`min_side`를 폴더 이름에 싣습니다(`Cs10kS2G2`, `Cs10kMs128G2`). 이전에는 창 모양이 이름에 없어 **다른 창이 같은 폴더를 덮어썼습니다** — 헤드라인 폴더를 지킬 수 없는 상태였습니다. 기본값(4 / 256)에서는 이름이 그대로라 **이미 쓰인 모든 폴더의 이름이 보존**됩니다(테스트로 고정, 485개 통과).
- 채점: `eval/eval_jf.py` → MUVOD basic/complete, 17장면, 21프레임. 대조군은 기록된 헤드라인 값.

## 3. 판정 규칙(고정)

- **채택**: 17장면 **basic Δ ≥ +0.3점** **그리고** 최악 장면 Δ ≥ **−0.3점**.
- 두 팔이 모두 통과하면 **Δ가 큰 쪽을 채택**합니다. 두 팔 중 최대를 고르는 것은 추정치를 조금 부풀리므로, 채택값은 "절제로 고른 값"이라고 명시해 보고합니다.
- 어느 팔도 통과하지 못하면 **이 손잡이는 닫고** 헤드라인을 그대로 둡니다.
- **구현 확인(판정 전에 통과해야 함)**: 대상 규칙은 `--crop-small`에만 의존하므로 **세 팔의 대상은 349쌍으로 같아야** 합니다. 비대상 PNG는 헤드라인과 바이트 동일해야 합니다. 어긋나면 판정하지 않고 원인을 먼저 찾습니다.
- **보고만**: 팔별 대상/채택/되돌림과 사유, 확대율 분포, 확대율로 되돌려졌던 61쌍의 운명, 이미 채택된 278쌍의 운명, 장면별 Δ, 실행 시간.

## 4. 예측

1. `scale 2`: 되돌림 **71 → 15\~30쌍**. 확대율 사유는 **≤4쌍**(이미지 클램프분)으로 줄고, 대신 **창 가장자리 사유가 1 → 5\~20쌍**으로 늘 것(창이 좁아져 객체가 21프레임 안에 벗어남).
2. `scale 2`의 basic Δ = **+0.30 \~ +0.80점**.
3. `scale 3`의 Δ는 `scale 2`보다 작을 것(확대율에 단조), **+0.15 \~ +0.50점**.
4. 최악 장면 Δ ≥ −0.3 (게이트 v2의 가장자리 규칙이 이탈을 잡으므로 바닥은 본류 출력).
5. 이미 채택된 278쌍의 순효과는 **0 \~ +0.2점**: 확대는 더 되지만 창이 좁아 여유가 줄어듦.
6. 실행 시간은 헤드라인 스윕과 ±15% 이내(세션 수가 같고 창은 어차피 1008로 리사이즈됨).
