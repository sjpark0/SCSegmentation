> 2026-10-13. 층: 2단계 진단(17장면 MUVOD basic). 사용자 지시로 진행합니다("2번부터 해줘").
> 근거: 1단계를 GeoSet-2로 바꾼 [stage1-E8.md](stage1-E8.md) 이후, "1단계 개선 요소를 2단계 추적에도 쓸 수 있는가"를 검토했습니다(6-에이전트 조사·설계·반박 검토, 세션 기록).

## 1. 알려진 사실 (실행 전, GPU 0)

### 같은 모듈인지

- 2단계 추적기의 기억 어텐션은 `sc.predictor.model.tracker.transformer.encoder`입니다. 정체는 `TransformerEncoderCrossAttention` 4층이고, `build_scsam3._create_tracker_transformer`가 만듭니다. 호출 위치는 `SCSam3TrackerPredictorNewMem.py:1543`입니다.
- 2D 저장소(`SCSegmentation2D`, 브랜치 `geomem`)는 같은 패키지 `SCSam3/demoSCSam3MVOpt`로 모델을 짓습니다. 미세조정 체크포인트의 `memory_attention` 키는 같은 모듈의 `state_dict`입니다.
- 실측: 다섯 fold 모두 106개 텐서(fp32)입니다. 컨테이너 CPU에서 `_create_tracker_transformer().encoder.load_state_dict(…, strict=True)`가 **5/5 "All keys matched"**였습니다. 빠진 키, 남는 키, 모양이 다른 키는 0개입니다.

### 체크포인트

- `geoset_pred_ft`입니다. E8 채택 시드 `geoset_pred_ft_rep`을 만든 바로 그 체크포인트입니다.
- 장면 단위 5-fold이고, `geomem/folds.json`(sha256 `ab12356d…c0d7`)이 장면별 fold를 정합니다.

| 1 | AlexaMeadeFacePaint, Breakfast, FlameSteak, PoznanStreet | `8e043c4d48327ec2bbf69414bb06ad3e70e84094ccb9f96085e27323542a2518` |
| 2 | CBABasketball, Dog, Frog | `5b9ef4885d9e1f09caa88b5622c7b4442b57a11352447a5a26d8e7a8a0b7fc2f` |

| 4 | Barn, CoffeeMartini, MartialArts | `05402ec462fb0d90a0801c1b440e420639bdedf72832c2bfc6186b2db60b77af` |

### 학습 조건과 2단계의 차이 (분포 밖 요인)

학습 조건(2D `results-geoset2.md` §5, `geomem/wrapper.py`)은 다음과 같습니다.
- 다른 장면의 주석 카메라 3대, 프레임 0, 2, …, 20
- 기억 1~2개: c_ini 정답 기억 1개, 그리고 확률 0.5로 다른 카메라의 자기 예측 1개
- 모든 기억이 **조건 프레임 자리**(시간 인코딩 행 6, 포인터 위치 1)에 놓임
- 3D 거리 바이어스가 항상 켜짐
- 단일 마스크 출력

2단계에서는 이렇게 달라집니다.
- 행 6에 **자기 카메라의 시드**가 놓입니다.
- 이전 프레임 기억이 행 0~5에 들어옵니다. 학습 때는 본 적이 없습니다.
- 이웃 기억은 행 4(S4)에 놓입니다.
- 포인터가 최대 17개입니다.
- 바이어스는 없습니다. 이 진단에서는 넣지 않습니다.

학습된 바이어스는 −0.5~+0.6 로짓입니다(반박 검토 실측). 작아 보여도 어텐션 가중치를 약 0.6~1.8배로 바꾸는 크기이고, 가중치와 함께 학습됐습니다. 그래서 이 진단이 재는 것은 **"함께 학습된 바이어스 없이 가중치만"**이며, 결론도 그 범위로 한정합니다(3절의 "닫음" 포함).

### 크롭 재추적

- 크롭 재추적(`CropSmall`)은 **같은 추적기**(`self.predictor`)로 돕니다.
- 크롭 게이트는 크롭 결과의 프레임 1을 **프롬프트(시드)**와 비교합니다(`runMVSeg.py` `CropSmall`). 본류 마스크는 읽지 않습니다. 본류 PNG가 있는지만 세어 `frames_no_mainline_png` 칸에 적는데(E8 대상 340개 중 15개가 0보다 큼), 이 칸은 처치에 따라 달라질 수 있어 Z2 비교에서 뺍니다.
- 따라서 크롭 직전에 원래 가중치를 되돌리면 크롭 결과는 E8과 바이트 동일해야 합니다.
- E8 헤드라인의 크롭은 대상 **340**, 채택 **278**, 덮어쓴 PNG **5,560**입니다.

### 자동캐스트 캐시

- 추적기는 bf16 자동캐스트에 영구히 들어가 있습니다. 자동캐스트 캐시는 파라미터 객체를 키로 bf16 사본을 들고 있습니다.
- 그래서 제자리 `load_state_dict` 뒤에는 `torch.clear_autocast_cache()`를 불러야 새 값이 쓰입니다. 2D 저장소는 이 결함으로 결과 한 벌을 무효화한 적이 있습니다(`runs_invalid_autocast_cache/`).
- 교체 지점에서는 아직 본류 추적기의 기억 어텐션이 한 번도 돌지 않았습니다. 첫 호출은 `TrackForward` 뒤 쓰기 루프에서 일어납니다.

### 남은 손실의 위치 (E8 헤드라인, `jf_e8.json` CPU 재계산)

- **기준 카메라**의 프레임 0은 J&F 1.0000입니다(정답 시드). 프레임 1~20을 프레임 0 값으로 바꾸면 **+1.521점**입니다.
- 비기준 카메라에서 프레임 1~20을 각자 프레임 0 값으로 바꾸면 +0.615점입니다.
- 기준 카메라의 시드는 모든 실행에서 같습니다(정답). 다만 **헤드라인에서는 기준 카메라도 이웃 기억을 읽습니다.** 실제로 E8 헤드라인 세 구성의 기준 카메라 몫은 0.0676 / 0.0684 / 0.0665로 서로 다르고, 대조군 세 구성은 0.0853으로 모두 같습니다(`e8_contrib.json`).
- 따라서 이웃 영향 없이 기준 카메라를 가장 깨끗하게 읽을 수 있는 값은 **C-FT의 기준 카메라 기여**입니다. H-FT의 기준 카메라 기여에는 이웃 카메라 쪽에서 바뀐 가중치의 영향도 섞입니다.

## 2. 방법 (상수는 실행 전에 고정)

### 처치

새 플래그 `--ft-encoder geoset_pred_ft`를 씁니다.

- 기저 인자는 **글자 그대로 같습니다**.
  - 헤드라인: `--xview-window 1 --xview-mode C --xview-gate --xview-ptr --xview-tpos-shift 4 --ref-cam muvod --seeds-from MVSeed_geoset_rep --frame0-seed --crop-small 10000 --crop-gate v2`
  - 대조군: `--xview-window 0 --ref-cam muvod --seeds-from MVSeed_geoset_rep --frame0-seed`
- 순서는 다음과 같습니다.
  1. `RetireSpatialPredictor` 직후, `TrackForward` 전에 장면의 fold 체크포인트에서 `memory_attention`만 `strict=True`로 로드합니다.
  2. 자동캐스트 캐시를 비웁니다.
  3. 원래 가중치는 CPU에 복제해 둡니다.
  4. 헤드라인은 **`CropSmall` 직전에 원래 가중치를 되돌리고 캐시를 다시 비웁니다**. 대조군에는 크롭이 없습니다.
- 3D 거리 바이어스(`geo_bias`)와 3D 임베딩(`geo_embed`)은 **쓰지 않습니다**. c_ini 직접 읽기, 이웃 선택, 게이트도 기저 그대로입니다.

### 누출 검사 (실행 중단 조건)

- 체크포인트의 `fold`가 `folds.json[장면]`과 같아야 합니다.
- 체크포인트의 `scenes`(학습 장면)에 그 장면이 **없어야** 합니다.
- 체크포인트의 `arm`이 `geoset_pred_ft`여야 합니다.

### 폴더 이름

접미 `Ftgp`를 `Fs` 뒤, `Cs` 앞에 붙입니다. 순서는 Sd → Fs → Ft → Cs입니다. `--out`을 직접 줘도 `Ftgp`를 반드시 실어야 하므로, 기저 폴더를 덮어쓸 수 없습니다.

| 팔 | 폴더 | 기저 |
|---|---|---|
| **H-FT** (판정 대상) | `SegMaskSam3XW1CGPS4MSdgeoset_repFsFtgpCs10kG2` | E8 A2 `SegMaskSam3XW1CGPS4MSdgeoset_repFsCs10kG2` |
| C-FT (진단만) | `SegMaskSam3XW0MSdgeoset_repFsFtgp` | E8 A1 `SegMaskSam3XW0MSdgeoset_repFs` |

### 매니페스트

`ft_encoder` 블록에 다음을 기록합니다.
- 팔, fold, 체크포인트 경로와 sha256, `folds.json` sha256, 학습 장면 목록
- 인코더 파라미터 다이제스트 세 개: 교체 전, 교체 후, 복원 후
- 기능 탐침 다이제스트 세 개(같은 시점) 와 탐침 출력 dtype (3절 Z3)
- 크롭 전 복원 여부

GPU가 2장 이상 보이면 실행을 거부합니다. 작업자 프로세스에는 교체가 닿지 않기 때문입니다.

### 실행과 채점

- 순서: H-FT를 먼저(약 95분), 그다음 C-FT(약 52분)를 돌립니다. GPU 작업은 한 번에 하나입니다. 실행 체인은 `MVSeed/run_s2r5.sh`입니다.
- 채점: `eval/eval_jf.py` → `Data/MVSeg/jf_s2r5.json` (MUVOD basic·complete, 17장면, 21프레임)
- 판정: `MVSeed/s2r5_judge.py` → `MVSeed/runs/s2r5_judge.json`
- 통계: 장면 클러스터 부트스트랩(seed 0, 10,000회)

## 3. 판정 규칙 (고정)

**채택 대상은 H-FT 하나뿐**입니다. C-FT는 진단이고 채택하지 않으므로 다중비교 보정은 없습니다.

1. **채택.** 다음 넷을 **모두** 만족하면 새 헤드라인 후보가 됩니다. 학습된 2단계라는 단서가 붙습니다.
   - basic Δ ≥ **+0.3**
   - 95% CI 하한 > 0
   - 최악 장면 Δ ≥ **−0.3**
   - complete Δ ≥ 0

   기준은 2단계 R 계열 선례(+0.3 / −0.3)를 따릅니다. 학습을 쓰는 팔에는 최소 효과를 요구합니다.
2. **후속 열림.** 채택은 아니지만 다음 셋을 모두 만족하는 경우입니다.
   - H-FT basic Δ ≥ 0 (점 추정)
   - H-FT의 **기준 카메라 기여** ≥ **−0.05**
   - **C-FT의 기준 카메라 기여**도 ≥ **−0.05** (이웃 영향이 없는 깨끗한 읽기, 1절)

   이때 "미세조정 가중치가 시간축 추적을 해치지 않는다"로 읽습니다. 2단계 학습 계열(바이어스와 c_ini 직접 읽기를 더한 팔, 시간축 재학습)은 **각각 별도 등록**할 자격을 얻습니다.
3. **닫음.** 1과 2가 모두 아니면, 같은 시각 다시점용으로 학습한 가중치를 **함께 학습된 바이어스 없이** 2단계에 그대로 넣는 계열을 닫습니다. 시간축 재학습은 등록할 수는 있으나, 이 결과를 근거로 우선순위를 내립니다.

판정에는 **두 팔 모두 17장면**이 있어야 합니다. 하나라도 빠지면 판정하지 않습니다. 규칙과 예측은 반올림하지 않은 값으로 읽습니다.

**기준 카메라 기여**는 E8 기여 분해(`e8_contrib.py`)와 같은 식으로 계산합니다. 벤치마크 가중치 × (H-FT − 기저) 쌍 점수를 기준 카메라 행에 대해 합한 값입니다. 네 묶음(기준, F0, N0, 그 밖)의 합은 basic Δ와 정확히 같습니다.

**구현 확인(판정 전에 통과해야 함).** 하나라도 어긋나면 판정하지 않고 원인을 먼저 찾습니다.

- **Z1.** 두 팔의 프레임 0 PNG가 각 기저와 바이트 동일해야 합니다(`Fs` → 시드). 없는 PNG는 기저에서도 없어야 합니다(빈 시드).
- **Z2.** H-FT 크롭이 E8 A2와 같아야 합니다.
  - 대상 340, 채택 278, 되돌림 목록과 각 대상의 `iou_f1_seed`가 같아야 합니다.
  - 채택 쌍의 프레임 1~20 PNG(5,560개)가 **바이트 동일**해야 합니다.
  - 이것이 복원과 캐시 비우기가 작동했다는 증거입니다.
- **Z3.** 두 팔의 17장면 매니페스트 전부에서 다음이 맞아야 합니다.
  - 팔 = `geoset_pred_ft`, fold = 1절 표, 체크포인트 sha256 = 1절 표, `folds.json` sha256 = 1절 값, 학습 장면에 그 장면이 없음
  - 교체 후 파라미터 다이제스트 = 체크포인트 다이제스트, 교체 전과 다름
  - **기능 탐침**: 인코더의 모든 선형층에 고정 입력을 넣은 출력의 다이제스트입니다. 추적기가 도는 스레드에서, 그 자동캐스트 캐시를 거쳐 계산합니다. 교체 후 값이 교체 전과 달라야 합니다. 탐침은 교체 전에 원래 가중치로 한 번 돌려 캐시를 일부러 채워 두므로, 캐시 비우기가 빠졌다면 교체 후 탐침이 같게 나와 실행이 멈춥니다.
  - 헤드라인: 복원 후 파라미터 다이제스트와 탐침이 모두 교체 전과 같음
- **Z4.** 팔마다, 크롭 채택 쌍을 뺀 프레임 1~20 PNG 중 기저와 다른 것이 **1개 이상** 있어야 합니다. 교체가 계산에 닿지 않았다면 모든 PNG가 같고 Δ = 0이 되어 판정이 거짓으로 "후속 열림"을 낼 수 있기 때문입니다.

**보고만** 하는 것:
- 장면별 Δ
- 묶음별 기여(기준, F0, N0, 그 밖)
- 기준/비기준 프레임별 평균 J&F (프레임 0·1·5·10·20)
- 장면별 Z4 변경 PNG 수
- F0·N0 회복/파괴 수
- C-FT의 같은 항목
- H-FT Δ − C-FT Δ
- 실행 시간 (실행 체인 로그에서; 판정 스크립트 밖)

## 4. 예측

1. H-FT basic Δ ∈ **[−1.0, +0.3)**. 따라서 채택하지 않습니다.
2. H-FT의 기준 카메라 기여 ∈ **[−0.4, +0.1]**. 범위를 양쪽으로 잡았습니다. 가중치가 c_ini 자신의 추적에도 작용하기 때문입니다.
3. C-FT Δ와 H-FT Δ는 부호가 같고, 차이의 절댓값 ≤ **0.4**.
4. Z1~Z4는 모두 통과합니다. 구성상 성립해야 하는 확인이며, 증거가 아니라 배관 점검입니다.

예측 1·2는 반박 검토의 기대("0 근처, 음수 쪽 위험")를 숫자로 고정한 것입니다.
