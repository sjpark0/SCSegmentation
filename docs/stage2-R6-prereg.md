> 2026-10-13. 층: 2단계 후처리(17장면 MUVOD basic, GPU 0). 사용자 지시로 진행합니다("응 S2-R6로 진행해줘").
> 근거: 기준 카메라 손실 진단 [stage2-D-refloss.md](stage2-D-refloss.md). 손실 1.521점의 대부분은 시간 드리프트가 아니라 경계 정밀도였습니다.
> 특히 **움직이지 않은 물체**에서 SAM 3가 이미 정확히 아는 프롬프트 마스크를 매 프레임 다시 그리며 0.492점을 잃습니다(프레임 0 마스크를 그대로 두면 0.031점).
>
> 기저는 **이미 측정된 E8 실행**이며 다시 돌리지 않습니다.
> - 헤드라인 `SegMaskSam3XW1CGPS4MSdgeoset_repFsCs10kG2`: basic **92.173** / complete **87.507**
> - 대조군 `SegMaskSam3XW0MSdgeoset_repFs`: **90.711** / 86.110

## 1. 알려진 사실 — 그리고 이 등록의 한계

- **규칙은 이 17장면의 정답을 보며 설계했습니다.** 정지/움직임 구분(정답 프레임 0 복사 J&F), 특징 선택, 31 px 팽창, 기준 카메라 한정, (τ, δ) 격자가 모두 시험 정답 위에서 나왔고, 그 전에 팽창·수축·guided filter를 시도해 버렸습니다(진단 §4).
- 문턱: 진단 §5 격자(τ ∈ {0.6, 0.7, 0.8, 0.9}, δ ∈ {2, 3, 4, 5, 6, 8})에서 τ에 둔감(0.8 이하 거의 같음), δ가 좌우(δ 4~5 최대, 6부터 장면 하나가 −0.17 아래). **τ = 0.8, δ = 4는 고원 안쪽에서 손으로 고른 보수 값**이며 LOSO가 고른 값이 아닙니다.
- **헤드라인 팔의 결과는 이미 알려져 있습니다.** 같은 규칙의 오프라인 시뮬레이션이 basic Δ **+0.3645**(4,577 / 7,960 객체·프레임 교체)이고, 장면별 Δ는 최악 Fencing **−0.059**, Frog 0.000, 나머지 15장면 상승(최대 Dog +0.991)입니다.
  이 팔은 증거가 아니라 **"PNG로 실제화해도 시뮬레이션과 같은가"의 배관 점검**입니다.
- **정직한 추정은 LOSO뿐입니다**(장면 하나를 빼고 16장면으로 (τ, δ)를 고른 뒤 뺀 장면에 적용). 진단 §5 격자에서 **+0.387**(17/17번 (0.6, 5) 선택), 좁은 격자(τ 0.8~0.97, δ 2~10)에서 +0.364(16/17번 (0.8, 5)).
  LOSO는 문턱 선택만 덜어 냅니다. 규칙 계열 자체를 시험 정답으로 고른 몫은 덜어 내지 못합니다.
- **대조군 팔은 독립 검증이 아닙니다.** 두 팔의 기준 카메라 프레임 0 PNG는 바이트 동일(둘 다 정답 프롬프트)하고, δ 판정은 영상과 프레임 0 마스크만 보므로 **두 팔에서 같은 결정**을 내립니다. 대조군이 보지 않은 것은 τ뿐인데, 결과가 τ에 둔감합니다.
  그래서 대조군은 "추적 출력이 달라도 규칙이 해치지 않는가"의 **강건성 확인**으로만 씁니다. 기대값: τ 없이 δ = 4만 쓴 상한이 +0.566이므로(검토 실측), C-Rs는 그보다 조금 아래일 것입니다.
- 다른 카메라(1단계 시드로 시작)에는 쓰지 않습니다. 진단에서 같은 규칙을 시드에 걸면 손해였습니다(−0.02 ~ −0.22).
- **규약**: 쓰는 것은 MUVOD가 주는 c_ini 프레임 0 정답(이미 프롬프트로 쓰는 것)과 영상뿐이고, 프레임 t의 정답은 쓰지 않습니다. 준지도 VOS에서 프레임 0 마스크를 이후 프레임의 틀로 다시 쓰는 것은 정당합니다.
  다만 이득의 정체는 "더 잘 분할함"이 아니라 **"정지 물체에서 주석이 자기 자신과 일관된 것(복사 손실 0.031)을 이용함"**이고, 기준 카메라에만 도움이 됩니다.

## 2. 방법

`MVSeed/s2r6_snap.py`(컨테이너, cv2·numpy). 끝난 출력 폴더를 읽어 `<폴더>Rs`를 씁니다.

- 기준 카메라(`docs/raw/muvod_object_sets.json`의 `c_ini`)의 프레임 t ≥ 1, 각 객체 PNG에 대해
  `IoU(mask_t, mask_0) ≥ 0.8` **그리고** `mean |I_t − I_0|`(회색조 0~255, 영역 = mask_0을 31 px 원판으로 팽창) `≤ 4`이면 프레임 0 PNG로 바꿉니다.
  mask_0은 그 출력 폴더의 프레임 0 PNG(= 정답 프롬프트)입니다. mask_0이 비면 바꾸지 않습니다.
- 그 밖의 모든 PNG(프레임 0, 다른 카메라, 바꾸지 않은 객체)는 원본의 **하드 링크**입니다.
- 폴더별 `MANIFEST.json`에 규칙, 원본, 저장소 HEAD, 스크립트 sha256, 교체 수를 적습니다.
- 팔: **H-Rs** `SegMaskSam3XW1CGPS4MSdgeoset_repFsCs10kG2Rs`, **C-Rs** `SegMaskSam3XW0MSdgeoset_repFsRs`.
- 실행 체인 `MVSeed/run_s2r6.sh`: 스냅(두 팔) → 채점 `Data/MVSeg/jf_s2r6.json` → 판정 `MVSeed/s2r6_judge.py` → `MVSeed/runs/s2r6_judge.json`.
- 스모크(커밋 전, Fencing 헤드라인): 교체 33 / 160, 시뮬레이션 33과 일치, 원본과 다른 PNG 33개, 나머지 471개 하드 링크. 출력은 지움.

## 3. 판정 규칙

H-Rs가 채택 후보입니다. 반올림 전 값으로 읽고, 두 팔 모두 17장면이 있어야 판정합니다. 감시값 하나라도 실패하면 판정하지 않습니다.

- **채택**: H-Rs basic Δ ≥ **+0.3**, 95% CI 하한 > 0, 최악 장면 Δ ≥ −0.3, complete Δ ≥ 0, **그리고** C-Rs basic Δ > 0 이며 CI 하한 > 0(강건성).
  LOSO(+0.387, 실행 전 확정값)가 +0.3 이상이라는 조건도 이미 충족돼 있음을 적어 둡니다.
- **기각**: 그 밖.

**보고 규칙**(채택 시): 새 헤드라인 `…Cs10kG2Rs`를 쓸 때는 언제나 "시험 정답을 보며 설계한 기준 카메라 후처리"라고 밝히고, 이득은 실측 Δ와 함께 **LOSO +0.387**을 나란히 적습니다. ROADMAP·Notion·논문 초안 모두 같습니다.
이득은 "정지 물체에 주어진 프롬프트를 재사용"으로 서술하며 분할 성능 향상으로 서술하지 않습니다.

### 감시값

- **Z1** 기준 카메라 프레임 0과 다른 카메라의 모든 PNG가 원본과 바이트 동일, 두 폴더의 파일 집합이 동일(최상위 `MANIFEST.json` 제외).
- **Z2** 기준 카메라 프레임 1 이상에서 원본과 달라진 PNG는 모두 같은 객체의 프레임 0 PNG와 바이트 동일하고 모두 매니페스트의 교체 목록에 있음. 목록에 있지만 달라지지 않은 교체는 원본이 이미 프레임 0 PNG와 같은 것뿐. 교체 수 = 목록 길이.
- **Z3** 매니페스트의 규칙이 (0.8, 4, 31), 원본이 등록 폴더, 기준 카메라가 c_ini, 스크립트 sha256이 매니페스트 `git_head`에 커밋된 `MVSeed/s2r6_snap.py`와 같음. (작업 트리 변경 수는 기록만 합니다. 이 저장소에는 무관한 기존 수정 1건이 늘 있습니다.)
- **Z4** H-Rs의 basic 기준 카메라 기여가 시뮬레이션 +0.3645와 |차| ≤ 0.002, 다른 카메라 기여는 두 팔 모두 정확히 0.
