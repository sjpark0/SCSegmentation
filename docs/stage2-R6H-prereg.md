## 1. 알려진 사실

- MUVOD는 장면마다 **주석 카메라가 3대**(c_ini 포함)이고 정답은 시험 구간 21프레임뿐입니다. 그래서 다른 시점은 장면당 2개, 모두 **34개**입니다(`Data/MVSeg/*/Mask`, `docs/raw/muvod_object_sets.json`의 `cameras`).
- 원천은 이미 있는 **정답 프롬프트 실행** 두 개입니다(S1-E7, 2026-09, `Data/MVSeg/jf_e7.json`에 채점됨). 모든 주석 카메라가 자기 프레임 0 정답으로 시작하므로, 각 시점이 c_ini와 같은 처지(프레임 0 = 주어진 정답)입니다.
  - 주: `SegMaskSam3XW1CGPS4MSdgtFsCs10kG2` — 헤드라인 구성(교차 시점 기억 + 프레임 0 시드 + 작은 물체 크롭), 662개 다른 시점 프레임 0 PNG가 모두 정답과 같음.
  - 서술용: `SegMaskSam3XW0MSdgtFs` — 시점마다 독립 세션(교차 시점 없음).
- 정답 없이 미리 센 교체 수(`ref_snap.decide`): 주 원천 13 205 객체·프레임 중 **6 800**(51.5 %), XW0 13 104 중 6 489. 같은 객체·프레임에서 c_ini의 결정과 일치 92.1 %(카파 0.84), XW0 88.9 %(0.78).
- 설계 중 정답을 읽은 것(공개): 정답이 프레임 0과 화소까지 같은 객체·프레임 비율 c_ini 48.6 %, 다른 시점 44.4 %; S2-R6 이득의 65 %가 그런 프레임에 있음. MUVOD 논문(arXiv 2507.07519, §III-C)은 정지 물체를 첫 키프레임에만 주석하고 XMem으로 전파했다고 밝힙니다 — **S2-R6 이득의 일부는 이 주석 절차를 이용한 것**입니다. 또 [stage2-D-refloss.md](stage2-D-refloss.md) §5가 같은 규칙 계열을 1단계 시드로 시작한 다른 카메라에 걸어 손해(−0.02 ~ −0.22)를 본 것이 S2-R6를 c_ini 한정으로 만든 이유였고, [stage2-D-nonref.md](stage2-D-nonref.md) §2–3이 정답 시드의 다른 시점 손실(프레임당 0.12–0.17)을 공개했습니다.
- 그러므로 **양의 결과는 상당 부분 예상됩니다.**

## 3. 통계와 판정 (실행 전 고정)

- 채점: `eval/eval_jf.py`로 G·G+Rh·W·W+Rh를 한 번에 → `Data/MVSeg/jf_s2r6h.json`(컨테이너, jf_e14와 같은 방식). 다시 채점한 원천이 jf_e7과 다르면 기록합니다.
- 장면별 Δ = basic(G+Rh) − basic(G), `MVSeed/e7_judge.py`의 rows / scene_scores(객체 → 카메라 → 장면). c_ini의 기여는 정확히 0이므로 시점당 Δ = 1.5 × basic Δ.
- CI: `e7_judge.paired`(10 000회, Random(0)).
- **판정**(반올림 전, 17장면 모두 채점, Z1–Z4 통과일 때):
  - **REPLICATES**(재현) ⇔ basic Δ > 0, 95 % CI 하한 > 0, 어떤 장면도 Δ < −1.0 아님, complete Δ ≥ 0 — E8 상수 그대로, 새로 고른 것 없음.
  - **HARMS**(손해) ⇔ CI 상한 < 0.
  - 그 밖 **DOES NOT REPLICATE**(재현 안 됨).
- 크기 읽기(서술): 시점당 Δ의 CI 상한 < +1.094(= 3 × 0.3645, 설계 카메라 c_ini의 값)이면 "설계 카메라보다 작음", 아니면 "설계 크기".
