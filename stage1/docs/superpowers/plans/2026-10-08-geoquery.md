# GeoQuery (object-query hub, B-1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an object-query hub on top of `geobias_only_ft` — object queries read every view's tokens with a 3D object-cloud distance bias and are injected as a prompt token into every view's SAM decoder — train three arms with 5-fold CV, score on the 664-pair benchmark, and write `docs/results-geoquery.md`.

**Architecture:** New modules `geomem/objcloud.py` (reference masks → 3D object point clouds, token-to-cloud distances) and `geomem/query_hub.py` (`ObjBias`, `QueryHub`); a `GeoQuery(GeoMemStar)` subclass in `geomem/wrapper.py` that runs the hub once per scene and decodes each view with the query as an extra sparse prompt token (prompt encoder + mask decoder called directly, tail replicated); training/inference arms `geoquery_ft`, `geoquery_nobias_ft`, `geobias_only_ft2` warm-started from the same fold's `geobias_only_ft` checkpoint. The feature cache is extended to all views of the stride-2 training frames.

**Tech Stack:** PyTorch (scsam3 container via `scripts/docker_run.sh` / `scripts/test_torch.sh`), numpy + OpenCV on the host venv `.venv`, SAM 3 package in `../SCSegmentation/SCSam3` (read-only), existing `geomem/` and `mvseg2d/` modules.

**Spec:** `docs/superpowers/specs/2026-10-08-geoquery-design.md`

## Global Constraints

- Never modify files under `../SCSegmentation` (SAM 3 package); every change is instance-level or in this repo.
- `torch.set_autocast_cache_enabled(False)` is already done in `methods/sam3_single.load_model`; every GPU path must go through it.
- Never run two GPU jobs concurrently (cache build, training, scoring, torch tests).
- Image encoder, prompt encoder and SAM mask decoder stay frozen in every arm.
- Grid 72×72 = 5184 tokens per view, 256-d; pointer tokens 4 per memory view; object cap 16; `ObjBias`: 16 RBF centres uniform on [0, 2], σ 0.125, `w` zeros, `b_none` scalar zero.
- Training protocol: 5-fold `geomem/folds.json`, frame stride 2, 3 epochs, AdamW wd 0.01, cosine, seed 0, new modules lr 1e-3, memory attention + GeoBias lr 1e-5, no model selection.
- Hub subset in training K = 8 (reference + 2 targets + 5 random); all views at inference. Object clouds ≤ 256 points, coverage ≥ 0.5, seed 0.
- Evaluation checkpoints must come from a fold that did not train on the scene (`assert_no_leak`).
- Host tests: `.venv/bin/python -m pytest tests -q` (no torch on the host). Torch tests: `scripts/test_torch.sh <path>`.
- Branch `geoquery` (off `geomem`), main checkout (Data caches, checkpoints and containers live here).

## Review Focus

1. An object whose cloud is empty (tiny object, or all its reference cells invalid): every hub bias entry is `b_none`, no NaN/inf in the logits, the query still decodes. Test in Task 1 (`test_cloud_distances_empty_cloud_is_inf`) and Task 2 (`test_objbias_inf_distance_gives_b_none`).
2. A scene with fewer than 8 cameras: the hub view list is all cameras, without duplicates, reference first. Test in Task 4 (`test_hub_views_small_scene_uses_all`).
3. A view whose grid is entirely invalid (far hemisphere camera) in the hub token set: its tokens remain attendable with bias `b_none`, mass over views still sums to 1. Test in Task 2 (`test_queryhub_mass_sums_to_one_with_invalid_view`).
4. A random hub view whose feature cache is missing: training fails immediately with a `FileNotFoundError` naming the `.pt` path (no silent fallback to annotated views only). Test in Task 4 (`test_load_sample_pair_missing_hub_cache_names_file`).
5. The query token must actually reach the decoder: with a non-zero query projection the output must differ from the no-query output, and with zero gates it must agree in sign > 99.99 %. Test in Task 3 (`test_geoquery_zero_gates_matches_geobias_only`, `test_geoquery_query_changes_output`).

### Task 2: `ObjBias` and `QueryHub`

**Files:**
- Create: `geomem/query_hub.py`
- Test: `tests_torch/test_query_hub.py`

**Interfaces:**
- Consumes: `geomem.bias.rbf`, constants `N_RBF, RBF_MAX, RBF_SIGMA`.
- Produces:
  - `class ObjBias(nn.Module)`: `w [16]` zeros, `b_none [1]` zeros; `forward(dist: Tensor[M, L]) -> Tensor[M, L]` = `rbf(dist) @ w` where finite, `b_none` where `dist` is inf.
  - `class QueryHub(nn.Module)`: `__init__(dim=256, layers=2, heads=8, ffn=1024, use_bias=True)`; submodules `proj0: Linear(dim, dim)` (zero weight+bias); `layers: nn.ModuleList[HubLayer]` where each `HubLayer` has explicit cross-attention (`q_proj, k_proj, v_proj, o_proj: Linear`), `self_attn` of the same shape over the M queries, `ffn: Linear(dim, ffn) → GELU → Linear(ffn, dim)`, pre-`LayerNorm`s and scalar gates `g_cross, g_self, g_ffn: Parameter` initialised to 0; `obj_bias: ObjBias | None`; `proj_q: Linear(dim, dim)` zero-init; `type_embed: Parameter[dim]` zeros.
  - `forward(obj_ptr: Tensor[M, dim], tokens: Tensor[L, dim], dist: Tensor[M, L] | None, view_ids: Tensor[L] long (0..N-1)) -> (q: Tensor[M, dim], mass: Tensor[layers, M, N])` — explicit softmax attention in fp32 so `mass` (attention summed per view, averaged over heads) is available; `dist=None` means no bias.
  - `prompt_token(q: Tensor[M, dim]) -> Tensor[M, dim]` = `proj_q(q) + type_embed`.
  - `num_params()`.

import torch
from geomem.query_hub import ObjBias, QueryHub

def test_objbias_zero_init_and_inf_gives_b_none():
    b = ObjBias().cuda()
    d = torch.tensor([[0.0, 1.0, float("inf")]]).cuda()
    assert torch.equal(b(d), torch.zeros(1, 3).cuda())
