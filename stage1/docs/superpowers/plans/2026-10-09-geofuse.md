# GeoFuse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fuse every other view's backbone features, aligned by π³ geometry to the target's 72×72 grid, into the target's memory-attention input with a gated per-cell cross-view attention, trained on the `geoset_pred_ft` recipe (arm `geofuse_ft`).

**Architecture:** `geomem/align.py` projects target cells into each view and bilinearly samples that view's 72×72 features (occlusion-checked validity). `geomem/fusion.py` holds `ViewFusion` (self token + N aligned tokens per cell, 4 heads, zero-init output gate `g`). `GeoMemStar` gets an optional `fusion` module and `decode_view(..., aligned=(W, valid))`. A per-frame `sam3_feats72` cache feeds training; inference precomputes all views' backbones per scene.

**Tech Stack:** PyTorch inside the `scsam3` Docker image (`scripts/docker_run.sh`, `scripts/test_torch.sh`), host venv for torch-free tests and scoring (`.venv/bin/pytest tests -q`, `mvseg2d.evaluate/report/paired`).

**Spec:** `docs/superpowers/specs/2026-10-09-geofuse-design.md`

## Global Constraints

- Never modify upstream SAM 3 files; autocast weight cache stays off; never two GPU jobs at once (one background chain).
- `geofuse_ft` recipe = `geoset_pred_ft`: geobias_only base (`use_bias=True, use_geometry=False, no_rope=False`), SAM 3 init, 3 epochs, frame stride 2, `EXTRA_MEM_PROB 0.5`, `PRED_MEM_TAU 0.7`, AdamW (GeoBias + fusion 1e-3, memory attention 1e-5, wd 0.01), cosine, 5-fold, no model selection.
- Fusion only on the target decode's `vision_feats[-1]` (and on the predicted-memory view's decode); never on `encode_reference` / `encode_memory_from_prediction`.
- With `fusion=None`, `aligned=None`, or `g == 0` the decode is byte-identical to the current path.
- Occlusion tolerance `OCC_TOL = 0.01` (import from `geomem.warp_torch`); view set = all cameras of the scene (`meta["cams"]`, reference and target included).
- Result names `geofuse_ft_r1`, `geofuse_ft_rep` (`--gate reproj`). Pre-registered comparisons and success criteria: spec §5.
- Branch `geofuse` off `geomem`; commit after each task.

## Review Focus

1. A target cell that is invalid, or valid but visible in no view: the fusion must return the self feature exactly (no NaN, no −inf softmax). Pinned by `test_fusion_all_invalid_returns_self` (Task 2) and `test_align_invalid_target_cell_invalid_everywhere` (Task 1).
2. `sam3_feats72` whose camera order differs from `meta["cams"]`: alignment would pair geometry with the wrong features. Pinned by `test_level72_cams_match_meta` (Task 4): the loader asserts `cams == meta["cams"]`.
3. fp16 level-72 features and fp32 geometry: `align_views` must up-cast before `grid_sample` (fp16 grid_sample on CPU is unsupported and bf16/fp16 mixing silently loses precision). Pinned by `test_align_accepts_half_features` (Task 1).
4. `aligned=` must never reach `_heads` through `**kw` (the base `decode_view` forwards extra kwargs there): pinned by `test_decode_view_with_aligned_runs` (Task 3) which fails with a TypeError if it leaks.
5. A camera missing from `Cache/pi3` at inference (view geometry absent): the run must raise a `FileNotFoundError` naming the file rather than fuse with garbage. Pinned by `test_view_geometry_missing_names_file` (Task 1).

**Interfaces:**
- Produces: `ViewFusion(dim=256, heads=4)` with parameters `q_proj, k_proj, v_proj, o_proj (Linear dim→dim)`, `g (Parameter zeros(1))`; `forward(F_t [5184,dim], W [N,5184,dim], valid [N,5184] bool) -> (F' [5184,dim], stats: dict(self_mass: float, view_entropy: float, valid_views_mean: float))`.
